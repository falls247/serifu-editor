## 1. 目的と範囲

プリセットを1件変更したときのメインスレッド占有時間と、サムネイル選択から対象画像が表示されるまでの待ち時間を減らす。名前付きレイヤープリセットの共通経路を修正し、効果音だけでなくセリフ・吹き出し・キャプションにも適用する。

クリック時の文字サイズ変化も調査し、意図しないモデル更新が確認できた場合は修正する。原因未確認のまま全オブジェクトを固定70pxへ変更しない。

効果音のデザインテンプレートと長音線プリセットも共通更新処理の回帰確認対象に含める。PNGの画質やプリセットの見た目を変えて速度を稼ぐ変更、保存形式の変更、バックエンド・GPUへの移植は対象外。

## 2. 確認した実行経路

名前付きプリセットの変更イベントは `applyLayerPreset()` → `edit()` → `checkpoint()` → `applyPreset()` → `markChanged()` → `renderCards()` と進む。`renderCards()`の内部で`updateImageView()` → `sizePreview()` → `drawPage()`を実行した後、`edit()`末尾でも`drawPage()`を実行する。同じイベント内で`persistPreferences()` → `refreshPresetMenus()`も実行する。

| 処理 | コード上で確認した内容 | 根拠 |
|---|---|---|
| Undoの記録 | ページ内の全レイヤーをJSONへシリアライズする | [model.js](../../src/model.js#L224) |
| プリセット反映 | 種類別の書式を反映し、`normalizeLayer()`を実行する。SFXの既存letteringも正規化対象 | [presets.js](../../src/presets.js#L55)、[model.js](../../src/model.js#L97) |
| 変更後処理 | 選択中SFXにletteringがあればシーンを求め、変更状態・サムネイル予約・全体状態を更新する | [app.js](../../src/app.js#L1593) |
| カード再構築 | 対象ページのカードを全て破棄して作り直す。変更していないオブジェクトのカードも含む | [app.js](../../src/app.js#L1368) |
| LIVE PREVIEW | 対象ページの全オブジェクトを同期描画する | [app.js](../../src/app.js#L328)、[renderer.js](../../src/renderer.js#L546) |
| 重複描画 | カード再構築時の画像ビュー更新から描画し、その後編集処理も描画する | [app.js:1373](../../src/app.js#L1373)、[app.js:598](../../src/app.js#L598)、[app.js:1676](../../src/app.js#L1676) |
| 設定保存・メニュー更新 | 同期localStorage書込み後、マウント済み全ページの全レイヤーの候補を再構築する。既定IDだけの変更でも同じ経路 | [app.js](../../src/app.js#L2661) |
| フォント読込み完了 | グリフキャッシュを全消去し、全ページを再描画・サムネイル再予約する | [app.js](../../src/app.js#L54) |

全ページのメニュー更新はDOMを持つページが対象であり、未表示ページのカードを新たに生成するわけではない。サムネイル合成は70msのタイマー後に始まるため、変更イベント自体の時間と、変更後に続く停止を区別する。

効果音には追加の同期処理がある。`warpedGlyph()`のキャッシュ未登録時はCanvasのピクセル読出しと質感処理を行う。`密集レタリング`と`荒々しい手描き配置`はoptical kerningによる輪郭・配置計算も使う。これらの存在だけではユーザー環境の主原因と断定できない。

## 3. 再現と計測

### 3.1 プリセットの計測条件

静的調査を調査担当サブエージェント、隔離ブラウザでの実測を実験担当サブエージェントが実施した。アプリのファイルを書き換えず、Playwrightの応答差替えで関数別タイマーを挿入した。

- WSL2/Linux、Node.js 22.17.0、headless Chromium 141.0.7390.37、1600×1100、deviceScaleFactor=1、独立したBrowserContext。
- 元画像は1200×900px。小規模は1ページ・4オブジェクト、拡大条件は6ページ・各8個、合計48オブジェクト。セリフ・効果音・吹き出し・キャプションを混在させた。
- 効果音本文は`ゴゴゴゴゴッ!!`。標準の`縦書き・極太インパクト`（`sfx-impact`）を適用。反復時は`荒々しい手描き配置`（`sfx-handwritten`）へ戻してから適用した。
- ブラウザフォント読込み完了後350ms待機。冷条件は毎操作直前に`clearGlyphCache()`でglyph/layout/fontのJSキャッシュを消去した条件であり、ネットワークの冷条件ではない。拡大条件では対象ページの未変更オブジェクトもキャッシュ再生成の影響を受ける。
- 初回と反復を分離。SFX以外はセリフ`dialogue-large`、計測用の手描き吹き出しプリセット、キャプション`caption-handwritten`。吹き出しの値を標準プリセットの実測値へ読み替えない。

### 3.3 サムネイル選択の調査

サムネイルのクリックは[app.js:927](../../src/app.js#L927)から`activate()`へ進む。表示範囲をまたぐ場合、`syncVisiblePages()`が範囲外ページをアンマウントし、新しい範囲をまとめてマウントする。既定の表示件数は50なので、境界の移動や元の範囲への再訪では最大50行のDOMと画像ビューを準備する。

アンマウント時はCanvasを1×1へ縮小し、Canvas用画像の`src`を空にする。再訪時は再読込みを始め、`mountPage()`内の`renderCards()`・`sizePreview()`、画像の`onload`、`activate()`末尾などから描画を呼ぶ。ただし画像未準備の呼出しは早期returnするため、呼出し回数と実描画回数を分ける。同じ表示範囲内の選択には範囲全体のマウントし直しはない。

根拠：[activate](../../src/app.js#L774)、[unmountPage](../../src/app.js#L795)、[syncVisiblePages](../../src/app.js#L808)、[mountPage](../../src/app.js#L1491)。

実測は独立した2つのBrowserContextで各条件2回。OS・Chromium・画面寸法はプリセット計測と同じ。51ページ・表示件数50・各ページ1レイヤーとし、1〜50ページは640×480pxの軽いセリフ、51ページは3000×2000pxの効果音（comic、280px、burst、distortion45、roughness25、dryInk35、brushTails35）を配置した。対象Canvasは1400×933px。入力はローカルのdata URLであり、実ファイルやネットワークの転送時間は含まない。

| 操作 | クリックから対象Canvasの最初の成功描画完了 | マウント／アンマウント |
|---|---|---|
| 同じ表示範囲内の2ページ目を選択 | 12.6／14.5ms | 0／0 |
| 同じページを再選択 | 4.7／8.3ms | 0／0 |
| 2ページ目→未マウントの51ページ目 | 1144／985ms | 1／50 |
| 51ページ目→1ページ目へ戻る | 2177／2019ms | 50／1 |

51ページ目への移動では、表示範囲同期は約56ms、対象画像の`onload`はクリック約80〜86ms後。その後のSFX描画に約904〜1057msかかった。2 RAFまでは約75〜78msで到達していても、対象画像は表示できていない。**表示準備が非同期の場合、2 RAFだけを表示完了指標にしない**。51ページ目の再訪でも初描画まで約1.08〜1.10秒かかり、反復選択なら速いとは限らない。

1ページ目へ戻る操作では、50行の同期マウントだけで約1021〜1097msを要した。さらに`activate()`前半の`discardSam3Draft(previous)`内で、移動前の51ページ目を約806msかけて描き直す事例を確認した。そのページは直後にアンマウントされるため、この描画は不要だった。

経路は[app.js:782](../../src/app.js#L782) → [discardSam3Draft](../../src/app.js#L637) → [sam3-ui.jsのdiscard](../../src/sam3-ui.js#L525) → `render()` → `onPreview` → [drawPage](../../src/app.js#L1548)。`discard({notify:false})`でも`render()`内の`onPreview`は呼ばれ、通知抑制は描画抑制になっていない。

戻り時の対象画像`onload`はクリック約2013〜2173ms後、`src`設定から約1.2秒後だった。ただしDOM構築・旧画像描画によってイベント処理が待たされる時間を含み、これを画像デコーダ単体の処理時間とは呼ばない。旧ページ描画・同期マウント・画像準備は時間区間が重なるため、単純に足し合わせない。

smooth scrollの安定までの時間は、同一範囲内でも約0.67秒だった。視覚上の移動時間とCPU停止を区別し、スクロール演出の変更だけで描画遅延を解消したと判定しない。

計測クリック中はフォント準備済み、サムネイル合成の実行中ジョブは0件。背景サムネイル生成自体には約0.93〜1.40秒の処理を確認したが、クリックとの競合は今回未検証。`img.decode()`のPromise解決は描画後になる場合があり、デコーダ時間の指標として採用しなかった。関数別計測の追加により2回の計測のタイマー数は異なるため、厳密な統計比較ではなく再現確認として扱う。

### 3.4 クリック時の文字サイズ変化

通常の選択処理・`updateControls()`自体は`layer.size`を代入しない。ただしページを離れる時や入力欄のfocusoutでは入力値の確定処理を呼ぶため、入力欄とモデルの不一致も調査対象とする。

値81になる既存の正規経路は確認した。標準SFXのサイズ比率は幅1000に対して90、すなわち`sizeRatio=0.09`。幅900pxの画像で新規SFXを追加、または70pxのSFXへ`sfx-impact`を適用すると81pxとなる。記憶サイズ70pxは明示的な「反映」で使う設定で、新規作成時の既定サイズではない。ユーザーのクリック箇所は選択操作なので、この経路を報告事象の原因・解決とは扱わない。

根拠：[newLayer](../../src/renderer.js#L29)、[比率適用](../../src/presets.js#L55)、[SFX追加](../../src/app.js#L1908)、[記憶サイズ反映](../../src/app.js#L1922)。キャプションの自動調整による「表示文字サイズ」は、保存される`layer.size`とは別に計算する。

Canvasリサイズはpointermoveで箱の寸法比からsizeを変えるが、pointerupだけでは変更しない。移動閾値がなく微小移動による変化の可能性はあるものの、70→81には約15.7%の拡大が必要で、ユーザーの事象との対応は未確認。数値欄の選択だけと、スライダーの値変更・明示的リサイズを分けて再現する。

最小実測は900×600pxの2ページ、1440×1000の隔離headless Chromium 141で実施した。1ページ目にセリフ32px、通常SFX70px、lettering有効SFX70pxを置き、選択レイヤーID・モデルsize・プレビュー右側の共有サイズ欄を操作前後で記録した。

| 操作 | 有効試行 | 結果 |
|---|---:|---|
| 別のセリフを選択中に、通常SFXの中央をdown/upで選択 | 2 | モデル70を維持。共有欄は前の選択32→対象の値70へ同期 |
| 同じSFX中央の再クリック | 3 | モデル・共有欄とも70を維持 |
| lettering有効SFXの全体を中央で選択 | 1 | モデル・共有欄とも70を維持 |
| 右下リサイズハンドル上で移動なしのdown/up | 1 | resize開始判定はあったがpointermoveなし。モデル・共有欄とも70を維持 |

中央選択は計3回中、最初の1回が対象へヒットせず選択解除となったため除外した。カード見出し選択、サムネイルでのページ往復、同じサムネイルの再選択でもモデルsizeは変わらなかった。対照の標準プリセット明示適用と新規SFX追加では81を確認したが、選択クリックの再現とは扱わない。

**70→81は確認した選択条件では未再現・原因未特定**。選択により共有欄が別オブジェクトの値へ同期することと、同じオブジェクトの値が書き換わることを区別する。ユーザーの具体的なグリフ位置、個別文字編集モード、クリック中の小さなpointermove、発生前の入力状態は未確認。次の再現ではこれらとモデル・共有欄・変更したレイヤーIDを同時記録する。

| `src/app.js`：`edit()`／`renderCards()`／`updateImageView()`／`sizePreview()` | レイアウト更新が暗黙に描画し、その後もう一度描画する | 寸法・UI更新と描画を呼出し側で調整し、通常のプリセット適用では変更確定後のLIVE PREVIEW描画を1回に集約する。ResizeObserverやフォント完了による後続描画は別に管理する |
| `src/app.js`：`applyLayerPreset()`／`edit()` | 書式変更にも全カード再構築を使う | オブジェクトの追加・削除・並べ替えと、既存1件の書式変更を区別する。プリセット適用では対象カードの更新に絞る |
| `src/app.js`：カードの更新 | 全DOMを破棄し、入力欄・選択・details・スクロールを復元する | 既存カードを保ちながら必要な値・表示条件・要約・プリセットIDを同期する。構造変更が必要なら対象1件だけ再構築する |
| `src/app.js`：`persistPreferences()`／`refreshPresetMenus()` | 既定IDの変更でも全候補を作り直す | 優先度は低い。局所カード更新に必要な範囲で永続化と候補再構築を分離する。既定選択・削除ボタンは同期し、一覧の追加・上書き・削除・取込み時は全体へ反映する。主因対策の代わりにはしない |
| `src/app.js`：`activate()`／`discardSam3Draft()`、`src/sam3-ui.js`：`discard()` | ページを離れる際、破棄・取消処理が旧ページの全体再描画を呼ぶ | 取消・候補解放・UIリセットを維持しつつ、直後にアンマウントする旧ページのプレビュー更新を抑制する。同一範囲内で旧ページの選択枠を消す更新は別途必要な1回にまとめる |
| `src/app.js`：`syncVisiblePages()`／`mountPage()` | 最大50行の同期準備と画像再読込みが選択ページを待たせる | 選択ページを優先し、周辺ページは段階的に準備する。古い画像読込み・予約処理を世代で破棄し、表示順・スクロール・解放を保つ。提案ADR-0031に従う |
| `src/app.js`：サイズ入力確定・選択・ポインター操作 | 単なるクリックによる70→81は未再現・原因未確定 | 対象ページの共有サイズ欄・選択レイヤーID・モデルsizeを操作前後で比較する。古い値のflushや閾値未満の誤リサイズが再現した場合、その経路を修正する。比率プリセットのサイズ変更を選択不具合の修正として一律に無効化しない |
| `src/app.js`／描画関連 | プリセット操作の関数別計測がない | 操作内の時間、描画回数、後続Long Taskを測れる再現手順・計測を追加し、改善前後を同条件で比較する |
| 関連ブラウザ試験 | プリセットの機能確認が中心 | 全4種類について他カードの不要な再生成、選択・フォーカス・スクロールの喪失、候補一覧の不整合を検出する |

サムネイル選択は旧ページの不要描画抑制と選択ページの優先準備を必須範囲とする。容量制限付きの画像再利用は追加計測で必要性を判断する。全ページのデコード済み画像やCanvasを無制限に保持して再訪だけを速くする方式は採らない。

Undo記録の廃止や履歴上限削減で性能改善としない。単に`setTimeout`や`requestAnimationFrame`へ同じ重い描画を移すだけでは、占有時間が減ったとは判定しない。Worker化・分割処理を選ぶ場合は、応答性と画像表示完了までの時間をそれぞれ評価する。

実装順は、冷描画の内訳測定と対策選定、重複描画と旧ページの不要描画の削減、カード更新の局所化、選択ページの優先準備、文字サイズ変化の再現・対応、結合検証とする。主因に改善がなく、DOM更新だけ速くなった状態で完了にしない。

## 6. 維持する仕様とリスク

- 1回のプリセット適用を1回のUndoで戻し、Redoで再現できる。本文・ID・現在のXY座標・手動編集データの扱いを現行仕様から変えない。
- カードから適用したプリセットを当該種類の既定として記憶し、次回の新規追加・再読込み・保存データに反映する。localStorage失敗時の通知を維持する。
- プリセットの追加・同名上書き・削除・取込みでは、別ページを含む候補と参照IDを正しく更新する。更新範囲を狭めた結果、古い候補が残るリスクを検証する。
- SFX固有欄や自動サイズ調整、話者、色、輪郭、縦横方向、枠・テールなどの条件付き表示を同期する。単純に入力値だけを書き換えると表示が不整合になる。
- キャッシュ変更を採用する場合はフォント読込み前後の字形、質感seed、手動グリフ、長音線、重なり順、PNG出力の一致とメモリ上限を確認する。画質低下や古い字形の残留を許容しない。
- ページ選択の改善でも50／100／全表示、フィルター、並べ替え、選択状態、キーボード移動を維持する。遅れて完了した画像読込みや準備処理が、すでに移動した別ページの選択・スクロール・Canvasを上書きしない。
- 画像を解放する現行方針を変更する場合は、デコード済み画像・Canvas・字形キャッシュを別々に計上し、容量上限と解放条件を定める。速度改善と引き換えに大量ページの常駐メモリを無制限に増やさない。
- 選択ページを優先する段階的マウントと、寸法・UI更新から描画を分離する方針は提案ADR-0031へ記録した。Worker化など別の重要な設計変更を採用する場合も、実装前にADRを更新する。

## 7. 検証と成果物

実装時は最小の関連試験から実行する。

1. `node --test test/presets.test.mjs`と、変更した描画／配置／letteringに対応する単体試験。
2. 全4種類のプリセット適用・Undo/Redo・既定記憶・別ページの候補一覧・保存後の復元を確認するブラウザ試験。既存`npm run test:font-size-browser`を再利用し、今回の回帰条件だけ追加する。
3. SFXの質感・配置やフォント経路を変更した場合は、該当する`test:sfx-controls-browser`、`test:sfx-template`、`test:sfx-render`、長音線・PNG出力試験を選んで実行する。
4. ページ表示経路の変更には`npm run test:thumbnail-browser`、`npm run test:page-filter-browser`と`node scripts/paged-smoke.mjs`を使用する。高速連続選択、境界への移動・戻り、読込み失敗、画像編集後の再訪、原寸表示中の背景更新も該当範囲で検証する。
5. 関連試験が成功した後に`npm run check`、`npm run build`、`git diff --check`を実行する。変更の影響範囲に応じてブラウザ回帰を実行する。

修正成果物は共通プリセット経路の修正コード、原因に対応する回帰試験、同条件の改善前後の計測結果、残る制約の記録。実装着手時のHEADは`c53be9c`（本SOWのコミット）で、アプリのコードは調査時と同じ。ユーザーの後続の実装指示により作業した。実装のコミット・pushは未実施。

## 8. 実装後の受入条件

1. 通常のプリセット適用イベント内のLIVE PREVIEW描画が1回となり、全4種類で正しいカード内容・選択表示を維持する。非同期フォント完了などに起因する描画は別に数える。
2. 画像・書式・描画品質を揃えて比較し、各冷／反復温条件を最低5回計測する。新しいBrowserContextでの自然な初回、意図的なキャッシュ消去、反復温を混ぜず、中央値・最大・描画回数・キャッシュmiss数を記録する。
3. 冷SFXの同期時間は本書の基準値から中央値30%以上の短縮を暫定目標とする。小規模約213msに対し150ms以下、拡大約351msに対し250ms以下が目安。計測環境が変わった場合は同じ変更前コードを取り直し、同環境の改善率で判定する。これは提案目標であり、達成済みの値ではない。
4. サムネイル選択ではクリックから対象Canvasの最初の成功描画までを測り、周辺全ページの準備完了・2 RAF・スクロール安定時刻と分ける。旧ページのアンマウント前の不要なSFX描画を0回にし、選択ページ初描画が他49行の準備完了を待たない。上記合成データの範囲跨ぎ・戻りを各5回以上測り、初描画までの中央値30%以上の短縮を暫定目標とする。
5. 初回描画と画像選択の待ちが残る場合、内訳と残存Long Taskを明記する。DOM更新だけの改善や待ち時間のタイマーへの移動を、フリーズ解消の受入根拠にしない。
6. Undo/Redo、保存・復元、現在位置、手動編集、フォント完了後の字形、PNG出力が回帰しない。ページ準備・画像再利用を変更した場合は、連続選択による古い結果の混入がなく、容量上限とアンマウント時の解放を確認できる。単なる選択で文字サイズが変わる再現ケースを確定した場合は、その操作でモデルsizeと入力欄の値が変わらない回帰試験を追加する。

調査用の一時計測ファイルは`/tmp/serifu-preset-investigation/`の`measure.mjs`、`measurements.json`、`trace-render.mjs`、`render-trace.json`、`thumbnail-selection.mjs`、`thumbnail-selection-first.json`、`thumbnail-selection-substages.json`、`size-click-check.mjs`、`size-click-check.json`。各`.mjs`を`node`で実行した。ページエラーはなく、ブラウザ・サーバーを終了した。一時ディレクトリは消えるため、将来の実装では再現用計測をリポジトリの`scripts/`へ整備する。初回を含む元JSONの`warm`ラベルをそのまま集計せず、§3.2の初回・反復区分で扱う。
