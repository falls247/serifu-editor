- 作成日：2026-10-25
- 更新日：2026-10-25。追加依頼：アプリ無操作15分でのモデル解放と、UIからのしきい値変更。

- 状態：実装前の提案。今回の成果物は計画書。省メモリ化・無操作検出・しきい値設定UI・全解除の表示修正は未実装。

## 1. 目的と対象

初回・完全解放後のモデル読込みでCPUモデル、読込み中の重み、ファイルキャッシュが重なり、WSLの割当てメモリとディスク負荷が増える問題を改善する。既存の検出精度、テキスト／ポイント／候補修正、取消、モデル設定変更、アイドル解放の競合防止を維持する。

アプリを操作している間の不要な解放・再ロードも防ぐ。解放条件を、従来の「モデル準備・推論終了から既定10分」から「アプリ全体の無操作が既定15分」へ変更する。SAM3パネル以外の編集も対象とし、しきい値をUI上で変更・保存できるようにする。時間延長は再ロードの頻度を下げる対策であり、ロード処理そのものの省メモリ化・高速化とは別に評価する。

検出候補の「全解除」後に、古い候補マスクや一時的な加工結果が残る問題も解消する。候補の選択、元画像の重ね表示、ライブプレビューの未確定加工を整合させる。確定済みの加工マスクと未確定の検出候補は区別し、「全解除」で確定済みの加工を削除しない。

VmmemWSLの表示にはWSL全体のメモリが含まれるため、SAM3のプロセスメモリ、Linuxファイルキャッシュ、WSL割当て、Windowsの空きメモリを分けて評価する。「15GBを必ず何GBへ減らす」といった未計測の削減量は約束しない。

対象外：量子化、重みの精度変更、CPUモデルの常駐待機、モデルの自動ダウンロード、WSLの上限・swap・キャッシュ回収設定変更、推論方式変更。再起動後に推論エラーは再発していない。原因解消と断定せず診断ログを維持する。

## 2. 調査結果と制約

- 固定SAM3：`0570b3a5be9c4e694f23d85232fb55f4a6f1f7fc`、PyTorch 2.10.0、ローカル重み約3.45GB。
- 現行builder：CPUでモデルを実体化・初期化 → 重みをCPUへ一括読込み → `load_state_dict(strict=False)`でコピー → CUDAへ転送。
- 元のサーバーは418.484秒、再起動後は41.186秒。キャッシュ・メモリ状態の影響を含み、同条件の性能比較ではない。
- 独立計測ではCPUスレッド8でbuilder 214.300秒、スレッド1で34.613秒。測定順とキャッシュ状態が異なるため、差の全てをスレッド制限の効果とは扱わない。
- 診断中に空きRAM約175MiB、終了後swap約3.2GiBを観測。追加モデルの並列ロードは負荷を増やすため、以降の実GPU計測でモデルを二重起動しない。測定用モデルは必ず単一とする。
- SAM3の位置情報初期化は明示的な`device="cuda"`を含む。`meta`コンテキストを外側へ置くだけでは全ての実メモリ確保を防げない。
- 重みのキーをdetector／tracker向けに変換している。欠損キー、共有パラメータ、学習対象外buffer、事前計算キャッシュも互換性確認が必要。
- 現行の`model_idle_seconds`／`SAM3_MODEL_IDLE_SECONDS`は既定600秒。`JobManager._idle_expired()`は最後のロード完了・推論終了の新しい方を基準とし、通常の文字編集・画像切替・カード操作は見ていない。モデル設定APIは現在モデルパスだけを保存する。
- 「全解除」では`src/sam3-ui.js`が候補の`selected`を全てfalseにし、選択UI、`onPreview(draft)`、`drawOverlay()`を更新する。一方、`drawOverlay()`は未選択候補も輪郭と番号を描き、`hoverId`が一致すると内部も強調する。したがって選択解除だけでは候補表示そのものは消えないことをコードで確認した。利用者が報告した残留表示の全原因と断定しない。ライブプレビューの描画待ち・古い応答・表示キャッシュまで含む実ブラウザでの再現は未実施。

### OSファイルキャッシュの扱い

通常の運用ではOSキャッシュを手動でクリアしない。Linuxの回収可能なファイルキャッシュは必要時に再利用され、重みの再読込みにも役立つ。キャッシュ破棄は次回のストレージ読込みと初回相当の待ち時間を増やし得る。モデル解放時・起動時の`drop_caches`や管理者権限によるOS全体への操作をアプリに組み込まない。

Linux内の回収可能メモリとWindowsへ返却済みのメモリは区別する。Windows側が逼迫する場合はWSLの回収状態と設定を別途調べるが、本SOWではWSL設定を変更しない。モデル参照・不要な一時テンソルの解放と、OSのファイルキャッシュ回収を混同しない。

## 3. 提案する設計と実装順序

### P0：単一モデルで基準計測

起動ロード、完全解放後の再ロード、設定変更、失敗後の再試行を対象とする。依存、部品構築、重み読込み、割当て、GPU転送を区分し、段階の所要時間とプロセスのRSS（Resident Set Size：物理メモリ常駐量）・最大RSSを記録する。LinuxのMemAvailable、Cached、swap使用量、swap入出力、ディスク入出力、GPUメモリも採取する。可能ならWindows側VmmemWSLと空きメモリを別欄に記録する。

利用者の作業を中断する既存サーバー停止・再起動は事前確認する。比較のためにモデルを二重起動しない。OSキャッシュの強制破棄やswap無効化は行わない。

### P1：メモリマップ読込み

アプリ管理のローダーから、パス文字列を渡して`torch.load(checkpoint_path, map_location="cpu", weights_only=True, mmap=True)`を実行する。現行のファイルオブジェクト経由の呼出しをそのまま置換しない。detector／trackerのキー変換を維持し、不要なコピーを作らない。

まずCPUモデル構築を維持した段階で互換性とピーク削減を確認する。メモリマップは必要なページを遅延読込みする方式であり、全重みの読込み・ファイルキャッシュ・HDD待ちが消えるものではない。

旧形式などメモリマップ非対応を識別できる場合だけ、モデル構築前に従来経路へ切り替える。GPU OOMや任意のRuntimeErrorを捕捉して無条件に二度ロードしない。

### P2：空のモデル構造と直接割当て

`meta`デバイスでパラメータの形状だけを構築し、ランダム初期化用のCPUメモリと計算を省く。`load_state_dict(assign=True)`で読込み済みの重みを割り当て、CPU上の同サイズのコピーを省く。その後GPUへ転送する。

SAM3の明示的CUDA生成、位置情報キャッシュ、非永続buffer、共有パラメータを棚卸しし、必要な実体を正しいデバイス・dtypeで構築する。未ロードのmeta tensorが残らないことを検証してからreadyへ遷移する。現行の`strict=False`を根拠に欠損を黙認しない。既知の非checkpoint値だけを明示的に初期化し、想定外の欠損・余剰は診断可能なロードエラーにする。

インストール済み`.venv`の直接変更、`torch.load`やPyTorch全体へのグローバルな差替えは行わない。固定upstreamとの接点をアプリ側モジュールへ隔離する。私有APIを利用する場合は依存コミットと整合性テストを必須にする。

### P3：参照解放とCPUスレッド数の評価

GPU転送後、モデルから不要になったcheckpoint辞書・一時モデル・メモリマップ参照を速やかに解放する。GC（Garbage Collection：不要オブジェクト回収）やCUDAキャッシュ掃除だけでCPUメモリが必ずOSへ戻るとは扱わない。

CPUスレッド数の制限は省メモリ化と別条件で比較し、効果がある場合のみ導入する。プロセス全体への副作用、復元、ロード例外時の後始末を設計し、推論の速度を低下させないことを確認する。

### P4：アプリ無操作15分によるモデル解放と設定UI

#### 無操作の定義とモデル寿命

- 既定しきい値を900秒（15分）とする。SAM3の最終推論だけでなく、同じアプリ内の文字入力、キー操作、クリック、ポインタ移動・ドラッグ、タッチ、スクロール操作、画像追加・切替、カード設定、保存などの利用者操作を対象とする。元画像／ライブプレビューのFOCUS・原寸表示・モーダル・設定画面も含む。他のアプリを操作している時間は含めない。
- ユーザー操作に由来するイベントをアプリ単位で監視する。自動スクロール、描画、アニメーション、自動保存、health／jobのpoll、周期タイマー、APIの状態確認は利用者操作と扱わない。タブを開いたまま置くだけで保持期限を延長しない。
- バックエンドは`time.monotonic()`を基準に、最後に観測したアプリ操作、モデル準備完了、推論終了のうち最新の時刻から期限を計算する。モデル準備・推論が長引いても、その完了直後の解放を防ぐ。起動後にブラウザからの操作通知がなくても、モデル準備完了から15分で解放可能とする。
- モデル読込み中、推論実行中、待機ジョブがある間は解放しない。判定後もGPU lock取得内で操作時刻・設定・ジョブ・モデル世代を再確認する。新しい操作が到着したら古い期限の解放予約を無効化する。解放開始済みならGPU処理完了を待ち、次の明示的検出で再ロードする。
- 期限到達は既存maintenance周期内に確認する。UIには目安として表示し、15分ちょうどの即時解放を保証しない。ロード・推論中は解放保留であることを表示する。
- 未ロード状態のマウス移動や文字編集だけで再ロードしない。解放後の再ロードは従来どおり明示的なSAM3検出要求で開始する。起動時のロード方式は維持する。
- 複数タブ・ウィンドウは同じバックエンドモデルを共有する。どれかのアプリで操作があれば保持し、全クライアントから新たな操作がなくなった後に期限切れで解放する。画面を閉じたことだけを理由に他の画面のモデルを解放しない。

#### 操作通知と負荷・通信障害への対応

- 全画像で共有するクライアントに操作通知を集約する。ページ・マスクカードごとに監視や保持用タイマーを増やさない。イベントリスナーは登録先の寿命と合わせて解除し、再マウントで重複させない。
- 同一オリジンの`POST /api/sam3/activity`を追加する案とする。バックエンドのHost／Origin検証、リクエストサイズ・値検証、Node側のプロキシ許可リストを適用する。通知に入力内容、画像、キーの内容、ポイント座標を送らず、セッション・連番・直近の操作からの経過時間など最小限の情報だけを送る。
- 連続イベントは最大5秒程度の間隔でまとめ、操作があったときだけ送信する。時計変更に依存しないよう、送信時の操作経過時間を検証してサーバーの単調時計へ換算する。通知遅延による数秒のずれは計測に明記する。古い連番、別世代、長時間前の通知や再送キューを使って保持期限を後から延長しない。
- `visibilitychange`／`pagehide`では未送信の直近操作だけを可能な範囲で確定し、非表示中は保持目的の通信を続けない。再表示や再接続だけでは過去の操作を現在時刻へ更新しない。実際の新しい操作があったときに通知を再開する。
- API停止中・公開版では通知を抑制し、失敗時はバックオフする。通知失敗が文字編集を妨げない。通信断中の操作はバックエンドから観測できないため、モデル保持の保証対象外とし、復旧後の検出で再ロードできるようにする。

#### UIと保存する設定

- SAM3の共通設定に「無操作でモデルを解放するまで（分）」の数値入力を設ける。既定15分、提案範囲1〜240分・1分刻み。下限・上限は実装着手時に利用者の用途と照合する。無効化・常時保持は今回追加しない。
- 「保存」で確定し、未保存値・適用済み値・保存失敗を区別する。入力しただけでは適用しない。設定変更はモデルの再構築・GPU解放・ページ再読込みを発生させない。設定操作自身を利用者操作として計時を再開し、新しい値はその時点以降の無操作判定に適用する。
- UIは単位、最後の操作からの経過時間または解放までの目安、現在のモデル状態を表示する。設定パネルを開いているだけでは期限を延長しない。解放後の検出には再読込み待ちがあること、長い設定ではGPUメモリを長く占有することを説明する。
- 設定の正はバックエンドとし、ローカル設定ファイルへ原子的に保存する。起動時の優先順位は「保存済みの有効な値 → 明示的な`SAM3_MODEL_IDLE_SECONDS` → 新既定900秒」。旧設定のモデルパスだけでも正常に読み込めるようにする。秒単位の既存環境変数は維持し、分未満や整数分でない値があればUIで丸めて黙って上書きせず、現在の秒数も表示した上で次の保存から分単位へ移行する。
- モデルパスとしきい値を個別に保存できる部分更新へ設定APIを拡張する案とする。片方の保存で他方の値を消さず、既存のパス設定クライアントとの互換性を維持する。無操作設定だけの変更はモデル世代を更新しない。保存失敗時は実行時設定も旧値に維持する。
- health／設定応答に適用済みしきい値と無操作状態を追加し、複数パネル・タブへ反映する。保存前に開始した古い応答が設定を戻さないよう設定リビジョンを検証する。推論サーバーがない環境では設定変更不可の理由を示す。

### P5：「全解除」後の古い候補マスク・一時加工の残留を修正

#### 再現と期待する動作

- 「検出 → 全選択または個別選択 → 全解除」を基準に、残るものが元画像上の色付き塗り・輪郭・候補番号、ライブプレビューの未確定加工、以前の検出結果、確定済み加工のどれかを記録する。通常表示・元画像FOCUS・ライブプレビューFOCUS・原寸表示で対象を区別する。
- 「全解除」直後は選択数を0、全チェックボックスを未選択、確定ボタンを無効にする。未確定候補による古い塗り・輪郭・番号・加工結果を表示から除く。利用者がポインタを動かしただけでhover強調が復活しないようにする。
- 候補一覧と候補データは残し、一覧からの再選択・全選択で再度プレビューできるようにする。「全解除」を「キャンセル」や検出結果の削除に置き換えない。新しい検出結果では候補を確認できる初期表示へ戻す。「重ねて表示」の利用者設定を勝手に変更しない。
- 既にカードへ確定したマスク加工、文字、元画像、前景／背景ポイント、プロンプトは維持する。確定済みマスクを消すには、そのカードの非表示・削除を使う。候補解除を理由に確定済みマスクの履歴・保存データを変更しない。

#### 修正方針

- 選択状態と未確定候補の表示状態を整理し、「新しい検出候補の初期表示」「選択中」「全解除済み」を明確に扱う。全解除時にhoverと古い強調状態を無効化し、全解除後の未選択輪郭・番号を描かない。候補一覧からの再選択と新しい検出結果を、表示を復帰させる契機とする。単純なCanvas消去だけで済ませず、次の再描画も最新状態に従わせる。
- 元画像のoverlayとライブプレビューへ、同じ最新の候補状態から再描画を通知する。描画キュー・中間Canvas・合成キャッシュがある場合は、その無効化と世代確認を行い、遅延した古い描画が全解除後の画像を上書きしないようにする。キャッシュが原因と未確認のまま全キャッシュ破棄を追加しない。
- 全解除時点で実行中の最新検出要求は、選択表示の世代と分けて扱う。全解除より前に開始した要求の遅延応答で、解除した候補の選択・旧表示を復活させない。新しい候補を一覧へ採用する場合も全解除後の非選択・非表示方針を維持し、その後の明示的な再検出・再選択で復帰する。古いページ・旧要求・破棄済みUIの応答は従来どおり無視する。
- 画像切替、カード再マウント、FOCUSの開始・終了、ウィンドウのリサイズ、タブ復帰で全解除前の候補表示が復活しないようにする。プレビュー更新だけでは推論要求を追加しない。
- 未確定候補の状態を保存対象へ追加しない。PNG出力、原寸表示、一時保存、編集データは既存仕様と照合し、候補の残像や一時加工が確定済み加工として混入しないことを確認する。確定済みマスクがある場合の出力は維持する。
- 原因確定後に必要最小限の状態遷移・描画経路を修正し、実装結果には確認した原因と対処を記録する。GPUモデルのロード方式・無操作期限の変更とは独立して検証する。

## 6. リスクと完了条件

メモリマップはストレージ待ちが残り、meta対応はupstreamの内部構造への依存を増やす。欠損値の未初期化や共有関係の破壊は、ロード成功後の推論異常を招くため重点確認する。WSL上限だけを下げる対処はswapを増やす可能性があり、本実装の代替にしない。

無操作しきい値を延ばすとGPUメモリの占有時間も延びる。アプリ操作を通知できない通信断・ブラウザ制約があれば、操作中でも解放される可能性がある。操作通知を周期的なkeep-aliveに置き換えると無操作解放が働かなくなるため、実操作だけを通知する。モデルの解放とOSキャッシュの返却は別であり、解放直後のVmmemWSL表示の減少は保証しない。

全解除の修正では、新しい候補を選ぶための初期表示まで消してしまうことと、確定済みマスクを誤って消すことを防ぐ。候補選択・候補表示・確定済み加工の境界を説明書とテストで固定し、ユーザー報告の残留表示の原因は実ブラウザで確認後に確定する。

実装・互換性・最大使用量の実測・説明書判断・未確認事項を揃えて完了とする。コミットは別途許可後。今回のマスクUI改修は別作業であり、省メモリ化の実装実績に含めない。
