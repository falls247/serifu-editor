# SOW：SAM3モデル読込みの省メモリ化

- 作成日：2026-10-25
- 状態：実装前の提案。今回の成果物は計画書。バックエンドの省メモリ化は実装しない。
- 基準：`3d9b57c`、`fix/sam3-error-diagnostics`。着手時のツリーはクリーン。
- 関連：[調査記録](../docs/sam3-startup-investigation.md)、[モデルライフサイクルADR](../docs/adr/0032-sam3-model-lifecycle-and-status.md)、[提案ADR](../docs/adr/0033-sam3-memory-efficient-loading.md)。

## 1. 目的と対象

初回・完全解放後のモデル読込みでCPUモデル、読込み中の重み、ファイルキャッシュが重なり、WSLの割当てメモリとディスク負荷が増える問題を改善する。既存の検出精度、テキスト／ポイント／候補修正、取消、モデル設定変更、アイドル解放を維持する。

VmmemWSLの表示にはWSL全体のメモリが含まれるため、SAM3のプロセスメモリ、Linuxファイルキャッシュ、WSL割当て、Windowsの空きメモリを分けて評価する。「15GBを必ず何GBへ減らす」といった未計測の削減量は約束しない。

対象外：量子化、重みの精度変更、CPUモデルの常駐待機、モデルの自動ダウンロード、WSLの上限・swap・キャッシュ回収設定変更、推論方式変更。再起動後に推論エラーは再発していない。原因解消と断定せず診断ログを維持する。

## 2. 調査結果と制約

- 固定SAM3：`0570b3a5be9c4e694f23d85232fb55f4a6f1f7fc`、PyTorch 2.10.0、ローカル重み約3.45GB。
- 現行builder：CPUでモデルを実体化・初期化 → 重みをCPUへ一括読込み → `load_state_dict(strict=False)`でコピー → CUDAへ転送。
- 元のサーバーは418.484秒、再起動後は41.186秒。キャッシュ・メモリ状態の影響を含み、同条件の性能比較ではない。
- 独立計測ではCPUスレッド8でbuilder 214.300秒、スレッド1で34.613秒。測定順とキャッシュ状態が異なるため、差の全てをスレッド制限の効果とは扱わない。
- 診断中に空きRAM約175MiB、終了後swap約3.2GiBを観測。追加モデルの並列ロードは負荷を増やすため、以降の実GPU計測でモデルを二重起動しない。測定用モデルは必ず単一とする。
- SAM3の位置情報初期化は明示的な`device="cuda"`を含む。`meta`コンテキストを外側へ置くだけでは全ての実メモリ確保を防げない。
- 重みのキーをdetector／tracker向けに変換している。欠損キー、共有パラメータ、学習対象外buffer、事前計算キャッシュも互換性確認が必要。

## 3. 提案する設計と実装順序

### P0：単一モデルで基準計測

起動ロード、完全解放後の再ロード、設定変更、失敗後の再試行を対象とする。依存、部品構築、重み読込み、割当て、GPU転送を区分し、段階の所要時間とプロセスのRSS（Resident Set Size：物理メモリ常駐量）・最大RSSを記録する。LinuxのMemAvailable、Cached、swap使用量、swap入出力、ディスク入出力、GPUメモリも採取する。可能ならWindows側VmmemWSLと空きメモリを別欄に記録する。

利用者の作業を中断する既存サーバー停止・再起動は事前確認する。比較のためにモデルを二重起動しない。OSキャッシュの強制破棄やswap無効化は行わない。

### P1：メモリマップ読込み

アプリ管理のローダーから、パス文字列を渡して`torch.load(checkpoint_path, map_location="cpu", weights_only=True, mmap=True)`を実行する。現行のファイルオブジェクト経由の呼出しをそのまま置換しない。detector／trackerのキー変換を維持し、不要なコピーを作らない。

まずCPUモデル構築を維持した段階で互換性とピーク削減を確認する。メモリマップは必要なページを遅延読込みする方式であり、全重みの読込み・ファイルキャッシュ・HDD待ちが消えるものではない。

旧形式などメモリマップ非対応を識別できる場合だけ、モデル構築前に従来経路へ切り替える。GPU OOMや任意のRuntimeErrorを捕捉して無条件に二度ロードしない。

### P2：空のモデル構造と直接割当て

`meta`デバイスでパラメータの形状だけを構築し、ランダム初期化用のCPUメモリと計算を省く。`load_state_dict(assign=True)`で読込み済みの重みを割り当て、CPU上の同サイズのコピーを省く。その後GPUへ転送する。

SAM3の明示的CUDA生成、位置情報キャッシュ、非永続buffer、共有パラメータを棚卸しし、必要な実体を正しいデバイス・dtypeで構築する。未ロードのmeta tensorが残らないことを検証してからreadyへ遷移する。現行の`strict=False`を根拠に欠損を黙認しない。既知の非checkpoint値だけを明示的に初期化し、想定外の欠損・余剰は診断可能なロードエラーにする。

インストール済み`.venv`の直接変更、`torch.load`やPyTorch全体へのグローバルな差替えは行わない。固定upstreamとの接点をアプリ側モジュールへ隔離する。私有APIを利用する場合は依存コミットと整合性テストを必須にする。

### P3：参照解放とCPUスレッド数の評価

GPU転送後、モデルから不要になったcheckpoint辞書・一時モデル・メモリマップ参照を速やかに解放する。GC（Garbage Collection：不要オブジェクト回収）やCUDAキャッシュ掃除だけでCPUメモリが必ずOSへ戻るとは扱わない。

CPUスレッド数の制限は省メモリ化と別条件で比較し、効果がある場合のみ導入する。プロセス全体への副作用、復元、ロード例外時の後始末を設計し、推論の速度を低下させないことを確認する。

## 5. 受入条件と検証

1. 小さなテスト用モデルでメモリマップ・meta・assign・共有参照・非永続buffer・欠損キー・例外時の解放をGPUなしで検証する。
2. 実GPUで同一checkpoint・画像・入力を使い、テキスト、前景／背景ポイント、候補修正、4加工を確認する。重みのdtypeと値が一致し、同一条件の既存出力と候補・マスク・スコアを比較する。非決定的な差を許容する場合は理由と許容幅を明記する。
3. 起動、完全解放後、ロード中取消→次画像、設定変更、ロード失敗→修正後再試行が動作する。モデルの二重構築、解放後の残留参照、無限再試行がない。
4. 基準／変更後でプロセスの最大RSSとswap書込みが減ることを採用条件とする。各3回を目安とし、ディスクキャッシュの冷／温条件・Windows側負荷を区別する。キャッシュ強制破棄はせず、初回と反復を別集計する。利用者のメモリ逼迫が再発したら計測を中止する。
5. P1で互換性が保てなければ原因を記録して採用しない。P2で不明なbufferや共有重みを安全に扱えない場合はP1までを成果とし、meta対応済みと報告しない。
6. 既存の関連Pythonテストを最小範囲から実施し、`npm run check`・`npm run build`・必要なSAM3ブラウザ回帰を実行する。UI回帰はモックで行い、実GPUを無駄にロードしない。

## 6. リスクと完了条件

メモリマップはストレージ待ちが残り、meta対応はupstreamの内部構造への依存を増やす。欠損値の未初期化や共有関係の破壊は、ロード成功後の推論異常を招くため重点確認する。WSL上限だけを下げる対処はswapを増やす可能性があり、本実装の代替にしない。

実装・互換性・最大使用量の実測・説明書判断・未確認事項を揃えて完了とする。コミットは別途許可後。今回のマスクUI改修は別作業であり、省メモリ化の実装実績に含めない。

## 7. 技術根拠

- [PyTorch公式：Tips for Loading an nn.Module from a Checkpoint](https://docs.pytorch.org/tutorials/recipes/recipes/module_load_state_dict_tips.html)：mmap、meta、assignの組合せ。
- [Microsoft公式：WSL設定](https://learn.microsoft.com/en-us/windows/wsl/wsl-config)：WSL全体のメモリ上限・回収設定。今回は設定を変更しない。
- 固定SAM3のローカル`model_builder.py`と`model/position_encoding.py`を照合済み。
