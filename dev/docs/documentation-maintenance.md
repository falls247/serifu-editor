# 利用者向けドキュメントの更新ルール

制定日：2026-10-18。

## 文書の役割

- ルートの[README](../../README.md)：アプリ概要、公開版・操作説明書への入口、通常起動とSAM3の起動に必要な情報に絞る。
- ルートの[操作説明書](../../docs/index.html)：利用者向けの操作手順、保存・復元、ショートカット、対応範囲、トラブル対処をHTMLで説明する。表示スタイルは[manual.css](../../docs/manual.css)。
- `dev/docs/`：設計、実装、検証、開発運用の記録。内部の保存形式の版番号やテストコマンドは、利用者の操作に必要な場合を除きこちらへ記載する。

## アプリ改修時の必須対応

**この説明書の作成以降、アプリを改修した際は操作説明書への影響を確認し、利用者向けの動作に影響があれば同じ変更内で`docs/index.html`を更新する。説明書の更新を完了条件に含める。**

対象には次を含む。

- 機能の追加・変更・削除、ボタン名や入力項目、画面構成、操作手順。
- 初期値、制限値、選択・ドラッグ・ショートカットの動作。
- 読み込み、保存、出力、互換性、復元、保存場所の扱い。
- 対応ブラウザ・端末、SAM3の利用条件、エラー時の対処。

内部実装だけの変更で説明書の記載が変わらない場合は、変更報告やPRに「操作説明書への影響なし」と判断理由を残す。起動要件や手順が変わる場合はREADMEも更新する。詳細な操作説明をREADMEへ戻さない。

## 更新の進め方

1. 実装・画面ラベル・既定値を確認し、説明書の該当節を更新する。古い仕様を追記で残さず、現在の説明へ書き換える。
2. 機能の追加・削除で節構成が変わったら、目次と本文内リンクも合わせる。説明書を更新した際は冒頭の対象日も更新する。
3. `docs/index.html`は外部通信やJavaScriptなしでも読める状態を保つ。CSSは相対パスで読み込み、ファイルを直接開く場合・localhost・公開サイトのサブパスで確認する。
4. PC幅・スマートフォン幅で表示を確認する。見出し、リンク、表、キーボードフォーカス、印刷表示の読みやすさも確認する。
5. `npm run check`と`npm run build`を実行する。配信・ビルドを変更した場合は、ローカルの`/docs/`と`/docs/index.html`が開き、`_site/docs/`へHTML・CSSが出力されることを確認する。アプリの変更には別途、その変更に必要なテストを実行する。
6. 変更報告やPRに、更新した操作説明書の項目と確認結果を記載する。コミットはユーザーの許可後に行う。

新しい画像・CSSなどを追加する際は、`server.mjs`の配信許可リストと`scripts/build.mjs`の公開用コピー対象にも追加する。説明書から開発用の非公開資料に依存しない。

## 開発・公開手順の参照先

コード構成と検証の詳細は[引継書](HANDOFF.md)、設計判断は[ADR一覧](adr/README.md)を参照する。

```bash
npm run check
npm test
npm run build
```

`npm run build`はアプリ・操作説明書・準備済みの書体とライセンスを`_site/`へ出力する。静的配信先にNode.jsは不要。書体を含める場合は先に`npm run fonts`を実行する。

GitHub PagesはSettings → Pages → SourceをGitHub Actionsに設定する。既存の公開ワークフローはmainへのpushまたは手動実行で検証・ビルド・公開を行う。main／masterへの直接pushは禁止。マージや公開は、その時点のユーザーの指示に従う。
