# ADR-0026: 原寸プレビュー操作中の背景描画を遅延する

- 日付: 2026-10-11
- 状態: 採用
- 関連: [ADR-0025](0025-preview-magnifier-and-render-cache.md)

## 背景

原寸Canvasを再利用して表示を高速化しても、実際にスクロールを操作するまで待ちが残っていた。効果音4個を持つ3000×4200pxの画像を3枚読み込む負荷試験で、次を確認した。

- 100%表示のクリック処理は、同じ画像でも`activate()`によってLIVE PREVIEWを描き直してからモーダルを開いていた。
- モーダル表示中のResizeObserver・書体読込完了によって、背後のLIVE PREVIEWが再描画されていた。
- 予約済みのサムネイル更新もメインスレッドで合成処理を行う。

メインスレッドの描画処理がスクロール入力を待たせるため、Canvasが表示されるまでの時間だけでは操作開始の遅延を評価できない。

## 決定

1. 100%表示は通常の画像選択処理より先に開く。同じ画像の不要な再選択・再描画は省き、別の画像ならモーダルを開いた後に選択状態を更新する。
2. モーダル表示中のLIVE PREVIEW再描画をページ単位のSetへ登録して遅延する。モーダル表示中に予約タイマーが発火した場合と、サムネイルのデコード待ちから戻った場合も、通常のサムネイル合成を遅延する。利用者が開始した一括処理のタスクは継続する。
3. 閉じた後に`requestIdleCallback`で1ページずつ処理を再開する。非対応環境ではタイマーを使う。再表示中なら再開処理を止め、次に閉じるまで保持する。通常の再描画・再予約で処理済みとなったページ、破棄・アンマウントされたページは待ち行列から除く。
4. スクロールバーが実際に幅を占有する環境では、開く間だけルートの`scrollbar-gutter`を維持する。閉じたら元の設定へ戻す。通常表示の列幅やサイドバー幅を恒常的に変えない。
5. 原寸描画、倍率操作、画素内容と編集データはADR-0025の方式を維持する。初回の原寸Canvas生成に必要な描画時間は残る。

## 検証

- `scripts/full-preview-smoke.mjs`: 実際のホイールでスクロールが成立すること、モーダル中の画面サイズ変更・書体完了イベントで背景LIVE PREVIEWとサムネイルの描画が0回となること、閉鎖後にサムネイル更新が再開すること、既存の原寸画素一致・倍率・拡大鏡・数値精度。
- `scripts/preview-layout-smoke.mjs`: 27条件のレイアウト。
- `scripts/thumbnail-sidebar-smoke.mjs`: サムネイルの更新・並べ替え・保存・サイズ変更・モバイル表示。
- 構文チェック、静的ビルド、`git diff --check`。

`npm run benchmark:preview`は画像3枚・各3000×4200px・効果音4個を生成し、初回と再表示の操作開始から最初の実ホイールスクロールが成立するまでを計測する。結果は`artifacts/preview-interaction-performance.json`へ保存する。表示後のウィンドウサイズ変更も行い、背景再描画とLong Taskを数える。

| 参考計測 | 修正前 | 修正後 |
|---|---:|---:|
| 初回の操作開始〜スクロール成立 | 1034ms | 918ms |
| 再表示の操作開始〜スクロール成立 | 985ms | 175ms |
| モーダル中の背景再描画 | 3回 | 0回 |

数値は同じテスト画像を用いたWSL・headless Chromiumでの単回計測。ブラウザ操作の自動化待ちを含み、端末・描画内容によって変動する。背景を更新する時期が閉鎖後へ移るため、閉じてすぐのサムネイルは更新完了まで以前の表示を維持する。
