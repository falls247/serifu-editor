# ADR-0031：選択ページを優先して準備し、プレビュー描画を明示する

- 日付：2026-10-17
- 状態：**提案・未実装**。採用済みの判断ではない。
- 対象：[操作時の遅延・文字サイズ変化のSOW](../../sow/SOW_20261017_editor_interaction_fixes.md)
- 関連：[ADR-0008](0008-paged-editor-and-caption-outlines.md)、[ADR-0025](0025-preview-magnifier-and-render-cache.md)、[ADR-0026](0026-preview-interaction-priority.md)

## 背景

プリセット適用で`renderCards()`が画像ビュー更新を通じてCanvasを描き、その後`edit()`もCanvasを描く。冷キャッシュの効果音では最初の描画が同期停止の大半を占め、カード更新だけを省いても遅延が残った。

サムネイルから別の表示範囲へ移る場合、既定で最大50行のマウント処理が選択ページの表示に先行する。アンマウント時は画像とCanvasを解放するため、再訪には画像の再準備も必要となる。51ページの実験で、同一範囲内より範囲をまたぐ選択と戻りが大幅に遅くなった。具体的な計測条件と値はSOWに記録する。

同期UI更新に描画が暗黙に含まれる構造と、選択ページを表示範囲全体の準備から独立して扱えない構造が、待ち時間の制御を難しくしている。

## 決定案

### 1. 寸法・UI更新と描画を分ける

`renderCards()`、`updateImageView()`、`sizePreview()`の呼出し側が、最後に描画するかを明示できるようにする。既存の全呼出し箇所を確認し、リサイズ・画像編集など描画が必要な操作を維持する。通常のプリセット適用ではデータとUIを確定してから1回描画する。

これは重複描画の解消であり、冷キャッシュの重い1回を軽くする代替にはならない。字形・質感処理は別に計測・改善する。

ページを離れる時のSAM3ドラフト破棄も、取消・UIリセットとプレビュー描画を分ける。`notify:false`だけでは`render()`→`onPreview`を止められず、旧SFXページの描画で約806ms待つ実測事例があった。直後にアンマウントするCanvasは描画せず、同じ表示範囲に残る旧ページの選択表示は必要な更新だけ実行する。

### 2. 選択ページを先に準備する

表示範囲の構成を確定したら、選択ページのDOM、画像、描画を最優先する。他のページは順序を維持する枠を用意し、ブラウザへ制御を返しながら段階的に準備する。表示件数50／100／全表示は維持し、全ページの編集データは従来どおりモデルに保持する。

1行の準備自体が重い場合は、その1行の処理内訳も改善対象とする。タイマーへ移すだけで1秒の描画が短い処理になったとは扱わない。

### 3. 遅れて完了する処理を無効化する

ページ選択・表示範囲の変更ごとに世代を持つ。画像読込み完了、予約済みの周辺ページ準備、描画前に対象と世代を確認する。移動・削除・フィルター変更・表示件数変更・プロジェクト切替・アンマウントで古い予約を破棄する。

遅い画像が後から読めても、現在の選択やスクロール先を戻さない。解放したページへCanvasやオーバーレイを書き戻さない。

### 4. メモリとスクロールの制約を維持する

初期案では範囲外ページの画像解放を維持する。全ページのデコード済み画像・Canvasを常駐させない。別途画像キャッシュを追加する場合は、容量、対象、解放、失敗時の再試行を測定結果に基づいて決める。

周辺ページの準備で選択ページの表示位置がずれないように、枠の高さ・順序とスクロール補正を設計する。利用者が新たにスクロールした後、古い準備完了によって位置を強制的に戻さない。

## 代替案

- 表示件数を強制的に減らす：待ち時間を抑えられるが、50／100／全表示の既存操作を変える。選択ページの優先化を先に行う。
- 全画像・Canvasを保持する：再訪は速くなるが、大量の高解像度画像でメモリが増大する。無制限保持は採用しない。
- 全処理を`requestAnimationFrame`へ送る：実行時期が変わるだけで重い同期描画は残る。処理量と優先順の改善が必要。
- 直ちにWorker描画へ全面移行する：フォント・選択表示・画像編集・保存との整合性確認が広がる。まず主因の内訳を測り、局所的な処理削減と選択優先を評価する。

## 結果・リスクと検証

選択ページの表示を周辺ページ全件の準備から切り離せる。一方、同期処理を分割すると、素早い連続選択、破棄したページの読込み完了、フォント完了、原寸プレビューの背景遅延との競合が増える。世代判定、解放処理、スクロール保持を同時に実装する。

同一範囲・境界への移動・元の範囲への再訪で、対象初描画と全範囲準備完了を別に測る。描画品質、カード入力、Undo、画像編集、フィルター、保存内容とメモリ上限を確認する。実装と検証が完了するまで本ADRは提案状態を維持する。
