# ADR-0007: ページ配列の順序を保存とテキスト出力へ反映する

- 状態：採用済み
- 記録日：2026-10-10（日本時間）

## 背景

読込後にページ順を変更し、画面と書き出した画像・本文の順序を一致させる必要がある。編集済みだけを書き出す場合も、全体の何ページ目かをファイル名で判別できるようにする。本文の出力対象は女性台詞を既定とし、台詞1件ごとに「」で囲んで改行する。

## 決定

`app.js` の `pages` 配列をページ順の基準とする。「編集完了・次へ」の左に「ページ移動↑」「ページ移動↓」を置き、隣のページと配列・DOMの順序を交換する。先頭の↑と末尾の↓は無効。移動したページの選択、レイヤー、画像別Undo/Redo、確認済み・編集済み状態を保つ。

ページ移動はプロジェクトの変更として一時保存のrevisionを更新する。画像内容の編集には数えず、画像別Undo/Redoにも入れない。再移動で順序を戻せる。JSONと一時保存は既存のページ配列の順序をそのまま記録・復元できるため、編集形式はversion 6を維持する。

### 指定ページの直後への移動

「ページ移動↑」の左に、現在のページ番号を指定する入力と「移動」を追加する。0〜一覧枚数の整数を受け付け、0は先頭、1以上は移動前の該当ページの直後へ挿入する。たとえば `A, B, C` のAを3ページの後へ移動すると `B, C, A` になる。他のページの相対順序を維持するため、隣接交換と長距離移動を共通の削除・挿入処理へ統合する。

自分自身や直前のページを指定した場合は順序と保存revisionを変えない。空欄、負数、範囲外、小数はnumber入力の検証で拒否する。Enterでも実行でき、処理中は入力・実行を無効にする。移動先の番号入力は一時的なUI状態としてページの再マウント後も保持するが、編集データには保存しない。

移動後は既存のページ選択・サムネイル・ジャンプ一覧・表示範囲を更新し、移動したページの実行ボタンへフォーカスする。レイヤー、履歴、確認済み・編集済み状態は保つ。JSON・一時保存・PNG・TXTの順序は既存のページ配列を使うため、現在の編集形式version 9を維持する。

`export-smoke.mjs` で前後・末尾・先頭・Enter・不正値・自己指定・編集状態・保存と出力順を検証する。`paged-smoke.mjs` は500枚で50件表示の範囲を越える移動、入力とフォーカス保持、戻り先の本文と状態を検証する。390pxの画面でも新しい移動ボタン、↑、↓の順に配置し、横にはみ出さないことを確認する。

実行結果: `npm test`（15ファイル）、`npm run check`、ビルドが成功。上記2本と `preview-layout-smoke.mjs` のブラウザ検証も成功。[デスクトップ](../../../artifacts/page-move-desktop.png)と[モバイル](../../../artifacts/page-move-mobile.png)のヘッダーを目視確認した。比較画像はGit管理外。

### テキスト出力

「テキスト出力対象」と「テキストを保存」を追加する。対象は女性台詞（初期値）、男性台詞、すべての台詞、キャプション、効果音、すべての本文。全ページを現在のページ順で走査し、同じページでは中央のレイヤーカード順に出力する。

台詞は1件ごとに `「本文」`、キャプション・効果音は本文のみを出力し、各項目の末尾に改行を付ける。本文中の明示改行は保持する。空白だけの本文、空ページ、本文のない吹き出しは省く。対象本文がない場合は状態欄で通知する。

形式はBOM付きUTF-8、LF改行、ファイル名は `serifu-{target}.txt`。ブラウザのダウンロードで保存し、フォルダAPIがなくても利用できる。テキストのみの出力で画像の未保存状態を解除しない。

### 一括PNG

全体のページ番号と一覧枚数から `p{連番}_{元ファイルの拡張子を除いた名前}.png` を作る。桁数は一覧枚数の十進表記と同じ。9枚なら `p1_`、10枚なら `p01_`、100枚なら `p001_`、1000枚なら `p0001_`。OSで不正な名前文字は既存の保存処理と同様に置換する。

編集済みだけの抽出は、全体のページ番号を付けた後に行う。100枚中の2・7ページなら `p002_` と `p007_` になる。対象の少なさによって桁数を縮めたり欠番を詰めたりしない。単体PNGの既存の命名は維持する。

一括保存・編集済み画像一括保存は毎回 `showDirectoryPicker` を開き、最後に正常に画像を読み込んだフォルダハンドルを `startIn` で渡す。そのフォルダの画像が一覧からすべてなくなった場合は、一覧に残る接続済みフォルダを使う。接続なしの読込・復元時は初期位置を指定せず、ブラウザの既定を使う。出力先はダイアログで変更できる。

選択先の中に日時・UUIDを含む `serifu_...` フォルダを作り、PNGと対象ページの編集JSONを保存する。元画像を上書きしない。初期位置の適用はブラウザに依存する。フォルダハンドルは永続化しない。

## 代替案と比較

- DOMだけを並べ替える方式では、画面とJSON・保存・次ページへの操作の順序が食い違う。ページ配列を更新する。
- ページ順フィールドの追加は既存配列と情報が重複する。保存形式を変えず、配列順を使用する。
- 編集済みの画像を詰めて連番にすると、全画像保存と同じページの番号が変わる。全体のページ番号を採用する。
- 選択先へ直接PNGを置く方式は元画像との衝突を招くため、既存の新規出力フォルダ方式を継続する。

## 結果と制約

画像名が重複していてもページ番号で区別でき、同じ枚数ならファイル名の辞書順と画面順が一致する。一覧の追加・削除で桁数と番号は変わる。編集済み画像のみのJSONは対象ページだけを含み、未編集ページの本文・順序のバックアップにはならない。

ページ移動は画像別Undoで戻らない。テキスト出力は画像上の座標を読順として解釈せず、カード順に従う。JSON・一時保存から復元したページは元フォルダとの接続がないため、保存先の初期位置も復元できない。
