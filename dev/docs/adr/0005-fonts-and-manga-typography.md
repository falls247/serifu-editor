# ADR-0005: 固定した書体と字形画像で漫画表現を描く

- 状態：採用済み（既存実装の事後記録）
- 記録日：2026-10-10（日本時間）
- コード基準：`b721ad78a7c658f23b83a0da1f6ed13c950c9696`

## 背景

強い縦方向ブラー、歪み、文字のハネの掠れ、手描き風のばらつきをプレビューとPNGで再現する。添付TTFを台詞・効果音でも選択でき、縦書きの句読点を右上へ置く必要がある。書体の読込前に保存して代替書体が確定することも避けたい。

## 決定：書体の準備と配信

`fonts.js` を書体カタログの入口とし、21選択肢（同梱19＋端末2）を提供する。同梱書体は自サイトから配信し、実際の書体ウェイトを使用する。フォントファイルと規約は `scripts/fetch-font.mjs` がGit blob SHA-1で検証する。これは単純なファイルSHA-1ではなく、`blob <長さ>\0` を含むGit形式のハッシュである。

| 原本 | 保管と条件 |
|---|---|
| Google Fonts由来17書体 | 固定コミット `7085eb89a950e85db5b166b7a58d414544b4140c` からTTFとOFL規約を取得 |
| GEKIFUDE SFX | 添付原本をBase64でGit管理し、CC0規約を同梱。準備時にTTFへ復元 |
| 851チカラヨワク | 添付TTFをバイトを変えずGit管理し、作者の利用条件と参照URLを同梱。OFL／CC0として扱わない |

配信先の `assets/fonts/` は生成物としてGit管理外にする。通常のcloneは `npm run fonts` で再構成でき、過去のアップロード用ディレクトリを必要としない。添付書体の原本・規約は [assets/font-sources](../../../assets/font-sources) を参照する。

フォントは必要に応じて読み込む。読込後は字形キャッシュを破棄して再描画する。PNG保存は対象の台詞・効果音・キャプションの書体読込を明示的に待ち、失敗時は保存を中止してエラーを表示する。収録されていない文字はフォールバックし、特にGEKIFUDEの漢字・小文字は別書体になる場合がある。

## 決定：字形と効果

実フォントから文字ごとのアルファ画像を作り、インクの太さを膨張・収縮で変え、白縁とは別に扱う。縦横別のブラー、残像、行単位の歪み、掠れ、ハネを共通Canvas描画で適用する。インクの太さは−10〜30px、0.5px刻みで指定する。

文字ごとのサイズばらつきと左右ズレは `glyphSeed` と文字インデックスから決定する。新規効果音はサイズ5%・左右3%、旧データの欠損値は0%。コピー・保存・復元後もseedを保ち、描画のたびにランダムな位置や形へ変えない。

キャッシュのキーに書体・サイズ・太さ・効果・縦書きの向きを含める。中間字形は約200万ピクセルを上限に解像度を下げ、字形キャッシュは約500万ピクセルを目安に古い項目を除去する。極端な設定のメモリ増加を抑えるが、書き出すPNGの画像寸法は変えない。

## 決定：縦書きと先細り

書記素を `Intl.Segmenter` で分割し、利用できない場合はコードポイントへ分割する。縦書きの句読点 `、。，．､｡,.` は実際のインク領域を測って文字セル右上へ寄せ、長音・一部の括弧等は回転する。通常描画とインク画像の経路で同じ位置計算を使う。横書きの句読点にはこの補正を適用しない。

漫画エフェクト `effect='none'` と `effect='taper'` は集中線・震え・立体影を付けない。独立して設定したブラー・歪み・掠れは保持する。

先細りは文字インデックス `i`（先頭0）、基準サイズ `S`、変化率 `r` に対し `max(8, S × (1 − i × r / 100))` とする。初期率は10%、範囲0〜100%、0.5%刻み。100pxなら100→90→80pxの線形変化であり、直前の文字の90%へ複利的に縮める方式ではない。改行自体は数えず、折返し後もインデックスを継続する。個別文字の変動はその後に適用し、最小8pxを保つ。

`warp='taper'` は文字内の歪み、`effect='taper'` は文字列のサイズ変化であり別の設定。UIや保存形式で混同しない。

## 代替案と比較

- 外部フォントCDNへ常時依存すると、配信変更や読込状態の影響を受ける。固定版とチェックサムで再構成する。
- CSSの影・等方的ブラーだけでは、字形の掠れ・方向別ブラー・文字ごとの変形を出力PNGと共有しにくい。字形画像を加工する。
- 描画時のランダム生成は、プレビュー、コピー、保存で見た目が変わる。保存するseedを採用する。

## 結果と制約

表現の調整項目が増えるため、設定追加時はキャッシュキー・プリセット・正規化・拡縮・保存を一緒に更新する。ブラウザや端末フォントが違う場合のバイト一致は保証しない。

縦書きは必要な記号補正を実装した独自配置で、JIS禁則やOpenType縦書き機能の完全な組版エンジンではない。性能上、極端な拡大や効果では中間字形の精細さが低下する。フォント追加は原本・配布条件・実ウェイト・不足文字を確認する。
