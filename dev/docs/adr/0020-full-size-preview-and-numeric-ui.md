# ADR-0020: 原寸プレビューモーダルと数値UIの小数1桁表示

- 日付: 2026-10-11
- 状態: 採用
- 関連: [ADR-0015](0015-numeric-controls-and-glyph-fallback.md)、[ADR-0019](0019-multi-selection-and-image-edits.md)

## 背景

LIVE PREVIEWの幅をORIGINAL側の幅へ合わせた結果、広いプレビュー列でも画像が小さくなっていた。画面内に収めるプレビューとは別に、編集結果を原寸で確認したい。コピーや拡縮で生じる長い小数は数値欄の操作を難しくしていた。

## 決定

1. LIVE PREVIEWは自分の列幅と高さ上限から表示サイズを決める。ORIGINALは元画像列の幅を使い、両方とも画像の縦横比を維持する。ショートカットの常設説明、選択数の補足説明、操作後の案内からキー説明を外す。キー操作は維持する。
2. クロップの左に「100表示」を置き、標準の`dialog`で原寸プレビューを開く。元解像度の画像と全オブジェクトを描き、適用済みクロップ・回転を反映する。選択枠・操作ハンドル・未適用のクロップ範囲は描かない。縮小されたLIVE PREVIEWのCanvasは拡大せず、元画像から別Canvasへ描く。
3. 開くごとに100%へ戻す。100%は画像の1ピクセルをCSSの1ピクセルで表示する。倍率は10〜200%、10%刻み。拡大・縮小ボタン、倍率スライダー、100%ボタン、Ctrl＋ホイールで変更する。Canvasの画素を描き直さず表示寸法を変え、画像が画面を超えたらモーダル内でスクロールする。
4. ホイール操作ではカーソル下、ボタン・スライダーでは表示領域の中心を基準に倍率を変える。Ctrl＋ホイールのブラウザ拡大を抑止し、通常のホイールはスクロールへ使う。モーダル表示中は背景の編集ショートカットを抑止する。
5. 閉じるボタンとEscapeで閉じ、開いたボタンへフォーカスを戻す。閉じたらCanvasを解放する。画像と書体を待つ処理に世代番号を付け、閉じたモーダルや次に開いた画像へ古い処理が描画しないようにする。
6. 座標・サイズ・太さ・余白・角度・割合などは小数1桁まで表示し、数値欄とスライダーを0.1刻みで連動させる。seedと頂点数は整数のまま維持する。クロップ矩形は画像ピクセル単位の整数を維持する。
7. 読込・コピーなどで生じた内部の端数は表示だけ丸める。丸めた表示値を見たり、フォーカスを外したり、モーダルを開いたりしても内部データを変更しない。利用者が数値を編集した場合は小数1桁へ丸めて記録し、Undoで戻せる。編集データ版10は維持する。

## 代替案と結果

- 通常プレビューを拡大すると、1400pxに縮小された描画の細部を復元できない。原画像から原寸Canvasへ描く。
- 倍率ごとにCanvasの画素を増やす方式では200%表示時のメモリ使用量が増える。原寸Canvasを保持し、CSS寸法で倍率を変える。
- モデル全体の数値を丸めると、画像間コピーや読込だけで配置・設定が変わる。UI表示と利用者の数値変更に精度制限を適用する。

元画像と編集情報の画素を確認できる。大きい画像は原寸Canvasを使う分のメモリが必要になる。モーダルは確認用で、オブジェクト編集は通常の画面で行う。

## 検証

- `scripts/full-preview-smoke.mjs`: 1400pxを超える画像の原寸描画、全編集種類とPNGの画素一致、10〜200%の倍率操作、実際のCtrl＋ホイールとブラウザ倍率の維持、カーソル位置、通常スクロール、フォーカス・Escape、クロップ・回転、モバイル、小数1桁と0.1刻み、元データの端数保持。
- `scripts/preview-layout-smoke.mjs`: 24条件の縦横比と列幅を使うプレビュー、デスクトップの枠位置、サイドバー切替、モバイルの横はみ出し。
- 吹き出し・キャプション・効果音・文字位置のブラウザテストを0.1刻みと小数1桁の期待値へ更新。

実行結果: 単体テスト18ファイル、構文チェック、ブラウザテスト6本（原寸モーダル・表示レイアウト・吹き出し／キャプション設定・文字位置・効果音設定・画像編集）、静的ビルド、`git diff --check` が成功。
