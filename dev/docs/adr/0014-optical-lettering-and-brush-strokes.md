# ADR-0014: 変形後の文字輪郭と共通の可変線幅ブラシ

- 日付: 2026-10-10
- 状態: 採用
- 作業ブランチ: `feat/dialogue-balloon-controls`（ユーザー指定により継続）
- 関連: [ADR-0005](0005-fonts-and-manga-typography.md)、[ADR-0012](0012-distressed-ink-and-balloon-effects.md)、[ADR-0013](0013-speech-colors-and-balloon-parameters.md)

## 背景

実装開始時点では、吹き出しの輪郭はすでに7本の繊維パッチ方式だった。文字送りは変形前のサイズ・advanceを基準にし、サイズ変化・回転・歪みを反映した隣接字形の距離を評価していなかった。キャプションにはブラシ描画がなく、筆圧と質感も独立調整できなかった。

## 決定

1. `glyph-layout.js` に配置と局所字形解析を分離する。書記素分割、先細り、サイズ変化、記号回転と個別回転、縦横倍率、傾き、歪みの順に字形を確定する。Canvasの実インクメトリクスから変形後の領域を求める。詰め強度35%以上かつ隣接字の交差方向領域が重なる場合だけ、最大128pxの局所マスクから行／列のインク突出量を取得する。画面全体のピクセル探索は行わない。
2. 通常送りと輪郭間送りを詰め強度で補間する。輪郭の入れ子は小さい方の字形長の22%までに制限する。重なりは `overlapAllowance` と `glyphOverlap` の小さい方を使用し、主要字形の占有長に対する実重なり量を最大10.5%へ制限する。句読点には輪郭の入れ子を適用せず、従来の右上補正を維持する。
3. 手描き配置はseed付きの3文字周期の滑らかな変動80%と局所変動20%を混ぜる。サイズ・左右・上下・回転・字間には別系列を使う。配置後に隣接輪郭を補正し、インク領域で折り返し、全体の領域を算出する。新配置がボックスの88%を超える場合は、全体を均等に縮小する。
4. 最終描画と解析で `glyphInkSurface()` を共有する。縦書き句読点、回転記号、文字内の歪みを別実装にしない。掠れ・飛沫・白縁・残像は配置後の既存描画で適用する。
5. `brush-stroke.js` を吹き出し／キャプションの共通エンジンにする。基準Geometryを弧長に沿ってサンプリングし、鋭角頂点を明示的に含める。接線・法線、累積距離、周期的な筆圧、線幅、筆先角、不透明度を生成する。可変幅帯ポリゴンを私有Canvasへ描き、方向に沿った繊維・局所欠け・濃淡・弱い毛羽立ちをマスクへ適用する。頂点付近の揺れを抑え、miterを4倍までに制限する。
6. 閉曲線のノイズには整数周期の調和波を使用し、開始・終了で値と微分を連続にする。マスクを最終描画先へ合成し、背景・塗り・本文を削らない。本文クリップ、図形塗り、影、ヒット判定は元のGeometryを使用する。
7. 新しい通常線は従来のstrokeを継続する。旧データの文字配置は標準のまま、旧吹き出しブラシは `brushEngine='legacy'` で保持する。ブラシモード・ブラシパラメータを編集すると `pressure` へ移行する。新規レイヤーと新しいプリセットは `pressure` を使用する。
8. ユーザープリセットには配置seed／ブラシseedも保存する。これは今回の再現性要件に基づき、ADR-0005の「配置seedはプリセットに含めない」を更新する。組み込みプリセットはseedを指定せず、適用先のseedを保持する。旧ユーザープリセットでseedが省略されている場合も適用先を保持する。インク質感の `textureSeed` は従来どおりプリセット対象外。
9. プロジェクト版は9、描画キャッシュ版は5。旧版アプリによる新設定の欠落を防ぐ。JSONは1〜9、高速形式の内部プロジェクト版は6〜9を受理し、コンテナ版1とIndexedDBスキーマは変更しない。保存形式の版判定は既存の `PROJECT_VERSION` 共有処理を使う。
10. 変形字形メトリクス／輪郭プロファイルは512件、配置は64件または2万文字、最終字形は既存の500万画素、ブラシマスクは32件または600万画素に制限する。各ブラシサーフェスは200万画素まで。フォント読込時の既存キャッシュ破棄は配置・解析にも伝播する。

## 代替案の評価

- [perfect-freehand](https://github.com/steveruizok/perfect-freehand): MIT。筆圧ポリゴン生成は適するが、今回の閉曲線、テールの鋭角、既存形状の厳密な保持には専用の角処理と質感が必要。依存を追加せず、共通Geometryから独自の幅帯を生成する。
- 筆先スタンプ: 筆先形状には自由度があるが、細線の継ぎ目、閉曲線の開始位置、半透明の重ね濃度を調整する負担がある。今回は幅帯と独立テクスチャマスクを採用する。
- [opentype.js](https://github.com/opentypejs/opentype.js): フォントのアウトライン解析は可能だが、Canvas側のフォールバック字形との対応、フォントバイナリの追加読込、組版との整合が必要。Canvasの実描画と共通化できる局所アルファ解析を採用する。
- メトリクスだけの配置: [TextMetrics](https://developer.mozilla.org/en-US/docs/Web/API/TextMetrics) は実インク外接領域を取得できる一方、隣接字の窪みを評価できないため、必要なペアだけ輪郭プロファイルで補足する。

追加のランタイム依存、外部テクスチャ、ビルドツールは導入しない。

## 結果・制約

低い詰め強度ではメトリクス、高い強度では局所輪郭を評価する。最大128pxのマスクは精密なベクトル衝突検出ではなく、輪郭距離の近似。フォント・端末が異なる場合の画素一致は保証しない。極端な歪み、非常に狭いボックス、長文では全体縮小によって文字と間隔も小さくなる。

ブラシは人工的な筆圧と繊維であり、実際のペンタブ入力や任意の画像筆先を再現する機能ではない。極端な細長い尖形状と太い枠線ではmiter制限が作用する。大きな輪郭は200万画素上限で中間マスクを縮小するため、細かい掠れが弱くなる場合がある。

検証結果・比較画像・推奨値は [実装報告](../lettering-brush-report.md) を参照する。
