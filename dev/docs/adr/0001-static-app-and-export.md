# ADR-0001: 静的アプリと共通Canvas描画を採用する

- 状態：採用済み（既存実装の事後記録）
- 記録日：2026-10-10（日本時間）
- コード基準：`b721ad78a7c658f23b83a0da1f6ed13c950c9696`

## 背景

複数のローカル画像に台詞や効果音を付け、位置を確認しながらPNGへ保存する。GitHub Pagesで配信でき、画像をサーバーへ送らずに動く構成が必要。プレビューで調整した文字・エフェクトが保存結果にも反映される必要がある。

## 決定

HTML・CSS・JavaScriptのES ModulesとCanvas 2Dで構成し、画像の読込・加工・保存はブラウザ内で行う。アプリ本体にnpm依存パッケージ、画像処理API、ビルド用バンドラーは置かない。`server.mjs` はローカル開発用の静的配信だけを担う。

プレビュー、単体PNG、一括PNGは `renderer.js` の共通 `draw` を使用する。座標・寸法は元画像のピクセルを基準とし、`x`／`y` はレイヤーの中心。プレビューCanvasは長辺を最大1400pxに縮小するが、保存は元画像の解像度で描画する。出力では選択枠を描かず、使用書体の読込完了を待つ。

| 保存方法 | 決定した動作 |
|---|---|
| 単体PNG | Blobを生成し、ブラウザのダウンロード機能で保存する |
| 一括PNG | `showDirectoryPicker` で保存先の親フォルダを選び、日時・UUIDを含む新規フォルダへ連番PNGと編集JSONを保存する |
| 編集済みだけ一括 | `edited` の画像を先に抽出し、同じ一括保存経路を使う |
| 編集JSON | 画像・レイヤー・設定を含む持ち運び可能なデータをダウンロードする |

保存開始時に対象とレイヤーのスナップショットを取り、非同期処理中の選択状態に依存させない。元画像を上書きしない。途中で失敗した一括保存は作成済みファイルを残し、保存先と完了件数を表示する。

元画像の削除は、読込時のフォルダハンドルと確認を必要とする別操作。完全削除であり、レイヤーのUndoには含めない。フォルダAPIがない環境では直接一括保存・元画像削除を無効にし、代替読込と単体PNG／JSON保存を提供する。

## 代替案と比較

- サーバーで画像を合成する構成は、画像アップロード、サーバー運用、認証や保存先の管理を増やす。現在の静的配信構成では採らない。
- DOMやCSSだけでプレビューを描く構成は、PNG出力と別の描画経路になる。文字の歪みや掠れを共通Canvas処理へ集める。
- 元画像へ直接上書きする構成は、再編集前の画像を失う。新規出力フォルダを作り、元画像削除を独立させる。

## 結果と制約

プレビューとPNGの描画ロジックを一箇所で修正できる。効果の追加は共通描画へ入れ、プレビュー専用のCSS加工で済ませない。

処理はメインスレッド上で行い、多数の大画像や強いエフェクトの性能は端末に依存する。Canvasの出力制限、メモリ、フォルダAPIの利用可否はブラウザの制約を受ける。APIのない環境に直接フォルダ保存を保証する設計ではない。
