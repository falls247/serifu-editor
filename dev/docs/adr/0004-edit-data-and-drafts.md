# ADR-0004: 編集JSON、一時保存、プリセットの保存先を分ける

- 状態：採用済み（既存実装の事後記録）
- 記録日：2026-10-10（日本時間）
- コード基準：`b721ad78a7c658f23b83a0da1f6ed13c950c9696`

## 背景

PNG保存前に編集を中断・復元できること、任意タイミングと任意周期で保存できること、同じ設定を次の画像で使えることが必要。ブラウザを変える移行と、同じブラウザでの一時復元ではデータの持ち方が異なる。既存の保存データも読めるようにする。

## 決定

| 用途 | 保存先・形式 | 内容 |
|---|---|---|
| 持ち出し・バックアップ | ダウンロードするversion付きJSON | 画像Data URL、ページ名、全レイヤー、`done`／`edited`、プリセットと自動保存設定 |
| 作業中の復元 | IndexedDB `serifu-editor-drafts` | 編集メタ情報と元画像Blob。最新1件 |
| 次回の書式・既定 | localStorage `serifu.preferences.v1` | version 1の台詞／効果音プリセット、既定プリセット、自動保存設定 |

現在の編集形式は `PROJECT_VERSION=6`。JSON読込は1〜6、一時保存復元は3〜6を受け付ける。各レイヤーは `normalizeLayer` で種類・有限数・色・設定範囲・書体・列挙値を検証し、新しいレイヤーIDを発行する。

主な互換処理は以下のとおり。

- version 1の `bubble` は男性台詞へ移行する。現在の独立吹き出しとは別の旧形式であり、形状を引き継がない。
- 独立吹き出しはversion 4以降、キャプションはversion 5以降に対応する。
- version 5以前でキャプションの揃え方が欠ける場合は右／上を補完する。新規・version 6は中央／中央。
- 旧台詞／効果音データの欠損設定は既定値を補完する。例えば `taperRate=10`、文字ばらつきは0、`glyphSeed` は本文から決定する。

## 一時保存の整合性

IndexedDBのDBスキーマはversion 1のまま。編集データのversion 6とは別の管理番号である。`drafts` ストアのキー `current` と `images` ストアのページIDを対応させる。

編集メタ情報の更新、新しい画像Blobの追加、対象から外れた画像の除去を同じトランザクションで行う。すでに保存済みの画像Blobは書き直さず、元画像を不変データとして扱う。保存失敗時は成功扱いにせず、UIへエラーを表示する。

手動保存と自動保存の同時実行は `draftTask` で調整する。保存開始時のrevisionを記録し、保存中に起きた後続編集を保存済み扱いにしない。変更がない場合は自動保存を省略する。初期周期は2分、設定可能範囲は0.1〜1440分。処理中は自動保存をスキップするため、周期はバックグラウンドでの保存完了を保証する時刻ではない。

元フォルダのハンドルは永続化しない。JSON／一時保存から復元した画像は表示・編集・再保存できるが、元ファイルの削除権限は戻らない。

JSON読込は現在の画像一覧へ追加し、一時保存復元は一覧を置き換える。設定は `mergePresets` で未登録IDのユーザープリセットを追加し、既定選択を反映する。同じIDの既存プリセットは上書きしない。自動保存設定はJSON／一時保存に含まれるが、現行の読込では適用せず、現在のoriginの設定を使う。別環境へ移す場合は自動保存周期とON／OFFを再設定する。

## プリセットの境界

台詞／効果音だけがプリセット対象。本文、話者、乱数seedをプリセットに含めず、書式と配置を保存する。配置・寸法は解像度比、効果の割合はそのまま記憶する。`styleKeys` と `ratioKeys` が対象フィールドを定義する。新しい設定を追加するときは、既定値だけでなくこの一覧と旧プリセットの補完を更新する。

## 代替案と比較

- 大きな画像をすべてlocalStorageへ入れると同期書込みと容量制約の影響が大きい。画像BlobはIndexedDBへ分ける。
- JSONだけに保存すると、利用者が明示的にファイルを保存するまで自動復元できない。一時保存を併用する。
- ブラウザの保存領域だけに頼ると別環境へ移せない。画像込みのJSONを持ち出し用に残す。

## 結果と制約

一時保存・プリセットはoriginとブラウザに結び付く。GitHub Pagesからlocalhostへのclone、ポート変更、別ブラウザへの移行で自動共有されない。移行前に公開版から編集JSONを保存し、移行先で読み込む。一時保存は最新1件なので別タブから上書きされ得る。

JSONは画像をBase64で含み、元画像よりファイルサイズ・メモリ使用量が増える。IndexedDBの容量不足や保存制限もあり、長期バックアップの代わりにはしない。形式変更時はversionと読込可能版を意識し、既存データのテストを残す。
