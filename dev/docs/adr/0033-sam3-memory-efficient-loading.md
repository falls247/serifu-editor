# ADR-0033：SAM3のメモリマップと空モデル構築によるロード

- 日付：2026-10-25
- 状態：提案。未実装・未採用。
- 追加提案：アプリ無操作15分の解放とUIからのしきい値設定。ADR-0032の既定600秒・推論中心の判定は、本提案の実装後に置き換える。現時点の動作は変更していない。
- 対象：[省メモリ化SOW](../../sow/SOW_20261025_sam3_memory_loading.md)

## 背景

現行SAM3はCPU上のモデルを初期化後、checkpoint全体をCPUへ読み込み、重みをコピーしてCUDAへ転送する。モデル・checkpoint・ファイルキャッシュが重なり、WSLメモリとディスク負荷が増える。再起動後に推論失敗は再発せず、推論エラーの原因とロード時のメモリ増加を同一視しない。

## 提案する判断

固定SAM3依存との接続をアプリ管理のローダーへ隔離する。まず`torch.load(mmap=True)`、次に`meta`構築と`load_state_dict(assign=True)`を導入する。GPU lock・完全解放・取消・設定世代を維持する。明示的CUDA初期化、非永続buffer、欠損値、共有パラメータの互換性が確認できた段階のみ採用する。

`.venv`直接編集、PyTorch全体へのmonkey patch、無条件の再ロードは採用しない。量子化・精度変更・CPU常駐待機・WSL設定変更は今回の判断に含めない。

## 追加提案：アプリ全体の無操作による解放

既定しきい値を15分（900秒）とし、SAM3以外の文字編集・画像切替・ポインタ・キー・タッチなども操作として扱う。アプリ共有クライアントから実操作のみを集約通知し、バックエンドの単調時計で最後のアプリ操作・ロード完了・推論終了の最新時刻から計時する。health監視、自動保存、タブを開いたままの状態は保持期限を延長しない。GPU lock内の再確認と実行・待機中の解放抑止は維持する。

UIに分単位のしきい値設定と保存操作を設け、バックエンドへ永続化する。モデルパスの部分更新互換性と設定の原子的保存を維持する。無操作設定の変更だけではモデルを再構築・解放しない。複数タブの直近操作を合わせ、モデル不在時の通常編集だけでは再ロードしない。具体的な値域・イベント・通信障害・設定優先順位・受入条件はSOWのP4に記載する。

従来の600秒を900秒に置換するだけでは、文字編集を続けていても解放される問題が残るため採用しない。長いしきい値はGPU占有時間を増やす。OSキャッシュの強制削除は再読込みを遅くするため、モデル解放に組み込まない。

## 代替案と影響

- 現行方式の維持：保守は容易だが起動時の重複メモリと初期化コストが残る。
- GPU上で直接モデルを構築：CPU確保は減らせてもGPUピークと構築互換性の問題がある。
- WSL上限の縮小：Windows側の割当てを抑えてもswap・ディスク待ちが増える可能性がある。
- CPUモデル待機：再ロードは速くできるが常駐RAMを増やし、今回の目的と逆行する。

メモリマップだけでファイルI/OやWSLキャッシュはなくならない。meta対応はupstream内部構造への依存を増やすため、依存更新時に実GPU互換性を再確認する。単一モデルでピークと出力を比較するまで削減量は未確定。
