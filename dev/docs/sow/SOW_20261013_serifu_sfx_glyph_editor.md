### 0.3 回帰の原因と修正

旧CI [38351463618](https://github.com/falls247/serifu-editor/actions/runs/38351463618)と[38351219194](https://github.com/falls247/serifu-editor/actions/runs/38351219194)は失敗した履歴。今回の合格証跡には使わない。

H-01は保存／復元時にglobal activeを参照して別タブのprojectと混同し、復元用メタデータと素材を別々に取得する経路、再読込のlease引継ぎを修正した。タブのprojectIdを固定し、同一snapshotのbundleを読み、新document ownerへfenceを更新する。H-02はimage load後にSAM3のcontrolsを更新し、health完了が先行しても明示再検出を可能にした。

追加で編集行のmount時UI cache破棄、文字サイズ設定のcache key、Worker起動中cancel／次操作のgenerationを修正した。既存ブラウザsmokeのassert・期待値・30秒の待機上限は維持し、Promiseを返す保存確認の述語だけを`browser-wait.mjs`で正しくawaitしてpollする。端末書体の基準を揃えるためCIでNoto CJKを準備する。dev launcher単体試験は `/proc` で観測するPIDをfixtureから報告し、仮想PIDとの不一致による誤判定を防ぐ。終了assertとtimeoutは維持した。

保存中に追加された確定済み変更は、成功後に次の保存へ即時に引き継ぐ。画像hash・WebKitバイト変換の後、write transaction直前にleaseを更新する。ownerEpochで同documentの期限切れと別writerの介入を区別し、他writerが途中に保存した内容を古い準備で上書きしない。保存開始時にも最後の心拍からのwriter交代を確認し、latest再読込前の保存を拒否する。1秒／121秒保留・旧token拒否・writer交代とlatest再読込を`test:autosave-catchup`で確認する。

## 1. 目的・成果物・完了条件

併せてブラウザ内自動保存を、**プロジェクトID単位・最新状態と5分周期5世代の履歴分離・画像/マスク素材の参照共有・複数タブ排他・中断に強いトランザクション保存**へ移行する。

## 3. 効果音データモデルとテキスト同期 [FR-01]

### 3.1 不変条件

1. **原文 `layer.text` が正本**。個別グリフは原文のgrapheme位置に対応し、文字挿入/複製/削除は原文へ反映する。描画だけの隠し文字を作らない。
2. 既存の `kind:'sfx'` はページ内で従来どおり**1個のレイヤー**。グリフのZ順はSFX内部に限定し、他レイヤー間順序は変えない。
3. 個別文字のオーバーライドは**graphemeインデックス**に紐付ける。文字ごとの恒久UUIDを正本として使用しない。改行位置は別メタデータとして計算し、UTF-16添字を正本にしない。
4. 保存フィールドは `NaN/Infinity`、重複インデックス、範囲外の点列、循環・欠損参照を拒否/正規化する。外部JSONを無検証で描画しない。
5. 旧SFXは `lettering` フィールドを持たず、明示的に編集モードへ入るまで**従来の描画結果を維持**する。

### 3.2 保存構造の概念例（実装時にschema/バリデータを確定）

```js
{
  kind: 'sfx',
  id: 'layer-uuid', text: 'ザーーーーッ', x: 500, y: 400,
  // 既存style/effect/font/seed/size/w/h/rotation等は残す
  lettering: {
    schemaVersion: 1,
    enabled: true,
    layoutMode: 'overlap', overlapIntensity: 65,
    orientation: 'vertical',
    layoutSeed: 123456, inkSeed: 987654,
    glyphs: [
      // keyはgrapheme index。本文は常にlayer.textから解決
      {index: 0, dx: 0, dy: 0, rotation: 0, scaleX: 1, scaleY: 1,
       shear: 0, pivot: {preset:'center', x:0, y:0}, z: 0,
       overrides: {font: null, fill:null, outlineColor:null, outlineWidth:null},
       manual: {position:false, transform:false, style:false, z:false},
       orientationOverride:'auto', inkVariantSeed: 112233}
    ],
    strokes: [
      {runStart:1, runLength:4, mode:'continuous',
       path:{type:'bezier', points:[], handles:[]},
       widths:[{t:0,w:14,interpolation:'smooth'},{t:1,w:2}],
       start:{attach:'previous', relation:'touch', offset:0, detached:false,
              cap:'taper', sharpness:50, angle:0, length:12},
       end:{attach:'next', relation:'touch', offset:0, detached:false,
            cap:'round', sharpness:50, angle:0, length:0},
       lookOverride:null, manualLengthLocked:false, manualPoints:[]}
    ],
    outlineGroups:[{members:[0,1,2], mode:'auto', locked:false,
                    styleOverride:null}],
    arrangementBounds:{/* 派生キャッシュ。永続化するなら検証 */}
  }
}
```

この構造は**設計例**であり、必要十分な実フィールド名を実装時のADRで固定する。`stroke.runStart/runLength` は文字列との対応が正本であり、古いindex依存を直接持ち越さず編集操作ごとに再マップする。選択状態・ホバー・ドラッグ中の座標・IME入力中テキストは保存しない。

### 3.3 文字とレイアウト

- ダブルクリック、明示「文字単位編集」ボタン、モバイル操作からモードへ入る。旧SFXは入場時に自動・無確認で新形式へ変換し、Undoで戻せる。
- 各graphemeの位置、回転、縦横別倍率、せん断、9点プリセット/任意ピボット、描画順、個別書体/塗り/輪郭色/輪郭幅を直接または数値で編集する。高度なグランジ・ブラーは原則SFX共通。
- マルチ選択で移動・拡縮・回転・スタイル変更。共通中心を既定ピボット。異なる値は「混在」表示し、絶対値・差分加算・倍率を切替できる。
- 個別グリフを移動しても他グリフは移動しない（接続した長音線端点は追従）。SFX全体を拡縮した場合は文字・パスを比例拡縮。
- 自動配置は読みやすさ重視/重なり重視の2モード、重なり強度0〜100。手動操作後は衝突制限に強制的に戻さない。
- 自動再生成は固定seedから決定論的に計算。手動調整済みの位置等はロックして保持、未調整だけ再生成。約4案を比較できるUI。`layoutSeed`と`inkSeed`を分離。
- 複製時のランダムseedは既定で元を継承。テンプレート適用時は既定で新規生成。両方とも指定変更可能。
- 自動配置結果から手動位置/変形/スタイルだけをリセットできる個別・一括解除機能を用意し、他のスタイルは維持。
- `w/h`は手動配置した文字や線を収めるため**拡大方向のみ**自動更新（自動縮小なし）。編集用バウンディングボックスが大きくなってもページの画像サイズを変えない。

### 3.4 本文差し替えと編集同期

- 本文入力中はプレビューを描いても**未確定ドラフト**として保持。確定はblur／適用ボタン／Ctrl+Enter／保存・書出し・ページ移動時。Escで取消、Enterは改行、IME composition中は確定やショートカットを発火させない。
- 本文編集確定後は、**位置基準 / 同じ文字基準 / 全リセット**の継承モードを選択できる（既定モードはユーザーが選べるUI）。差分対応はgrapheme単位、繰返し文字でも決定論的にマッチさせる。未変更箇所の手動位置・個別スタイル・重なり順・曲線を優先保持。
- 新規文字挿入：手動配置済み文字は原則その場に保持。未調整の隣接文字だけ局所的に再配置。削除：手動位置保持＋未調整文字は局所詰め。位置優先の代替操作も用意。
- 個別文字複製は本文の元文字の**直後に同じ文字を挿入**。複数文字の複製は各元文字の直後にそれぞれ挿入。Ctrl+dragはドロップ位置、Ctrl+D/タッチ複製はオフセット、同座標複製コマンドも提供。
- 文字削除は原文から削除。連続長音線オブジェクトの削除では対応する `ー` のrun全体を原文から削除。
- Undo/Redoは操作1単位。移動/数値連続変更の適切な統合、差分再配置・端点追従・結合/分割などの派生更新も**1アクション**として戻す。

### 3.5 横書き・縦書き

- 同じSFX内部で複数行/列を保持。各行の自動配置と長音線runを独立管理し、手動文字は行境界を越えて自由移動可能。
- SFX全体で縦/横方向を切替。縦書きでは標準縦組み、1文字単位で正立/横倒し/縦中横を指定でき、手動rotationとは別プロパティ。
- 縦横切替で手動相対オフセット・長音線の方向を規則に沿って変換し、スタイル/倍率/個別回転を維持。切替→逆切替の往復テストで著しい座標ドリフトがないこと。

**受入例 FR-01**: `ザクッ` を手動配置して `ボコッ` に変更した際、選択した継承ルールに応じた位置/見た目が復元する。`ド`を複製/削除した結果と `layer.text` が一致し、保存→読込→Undo/Redo/PNGの全経路で齟齬がない。

## 4. 連続長音線・ストローク編集 [FR-02]

### 4.1 文字列との関係

- `ー`が**2文字以上連続**したrunを既定で**1本の連続線**として表示。単独 `ー` は通常のフォント文字。ただし個別に長音線モードへ切替可能。
- ソースの `ー` 個数により線の既定長さを更新。ただし手動で長さをロックした場合は固定/解除できる。**隣接文字にアタッチされた端点の追従を、長さロックより優先**（その端点がdetachなら例外）。
- runをフォント文字モードへ切り替えられる。線⇄フォント文字の切替で原文と保存済みの曲線編集データを失わない。
- ストロークはrunごとに独立操作。各行の `ー` は行内の独立runとして扱う。

### 4.2 形状と制御点

- プリセット形状: 直線/円弧/S字/波形。可動ベジェ制御点を追加/削除、smooth/sharp/左右独立ハンドルを切替。
- 編集モードを「曲線制御点」「太さ制御点」に分け、両方表示するモードも提供。点の複数選択/移動/倍率/回転/太さ一括編集が可能。
- 幅は始終点を含む任意の幅キーポイントを保持し、補間をsmooth/linear/stepから選択。途中点は線長変更時に既定で比例追従し、特定点は固定にもできる。幅点は原則run相対位置 `t∈[0,1]` に保持。
- 筆先の形状は**始点/終点独立**で丸/平/先細り/筆払い。尖り度/角度/長さを変更。
- 既存曲線を「形状のみ」「太さのみ」「見た目のみ」「すべて」でコピー・ペーストでき、ストローク専用プリセットに登録可能。

### 4.3 自動接続と本文変更

- 始点/終点は左右（縦書きは進行方向前後）の**実インク輪郭**への接続を基本とする。相対オフセット、接触/文字内部へ重ねる/一定隙間を端点単位で指定。個別端点detachで固定化。
- 接続先文字の座標/倍率/回転/変形が変われば接続点を再計算。アタッチ位置の求解は長音線本体を含まず隣接文字インク輪郭から行い、循環参照を作らない。
- run途中に別文字が挿入されて分断されたら、元曲線を挿入位置の割合で幾何分割して両方へ継承。元の太さ/筆先/スタイルを可能な限り残す。
- 分断run間の文字が削除されて連結したら、曲線・制御点・太さをなるべく残して滑らかに接続。異なるスタイルの競合は「先頭runの設定を優先、後方の制御点を温存」を既定の決定論的ルールとし、片側の特殊capは連結点では除去する。必要なら手動編集可能。
- 接続していた文字が削除された場合は新しい隣接グリフへ再接続。存在しなければ端点固定。既にdetachされている端点はそのまま。
- クロスSFXのストローク貼付け時は、対応する `ー` runをコピー先本文に挿入し、曲線/太さ/端点形状を引き継ぐ。色・フォント等の外観と接続先はコピー先SFXの条件で再解決する。

### 4.4 描画

- テーパーや幅プロファイルに沿った滑らかな閉じた面/アウトラインを描画。拡大縮小時も継ぎ目・尖端崩壊を防止。
- 色/輪郭等はSFX共通を継承し、ストロークごとの外観オーバーライドも設定可能。
- 描画中の高速プレビューと、ポインタを離した時/PNG保存時の最終品質を分離。キャッシュキーにrun・形状・サイズ・効果・字体/seedを含む。

**受入例 FR-02**: `ザーーーーッ` の線を手描きS字・左太右細で保存し、`ー`を増減/途中に `ク` を挿入/削除しても、意図した線分の曲線と太さが維持される。端点接続、detach、Undo、PNG、再読み込みが一致する。

## 5. 重なり・一体化輪郭・グランジ [FR-03]

- SFX内部の描画順を編集可能。既定は後続文字が前面。クリックで前面グリフ選択、Alt+clickで背面を順次選択、文字一覧/タッチでは選択対象を巡回。
- **外側輪郭モード**を「個別輪郭」「文字集合を包む外側輪郭」から切替。重なりに応じてグループを自動生成し、メンバー手動追加/除外が可能。
- グループは共有輪郭スタイルを継承し、グループ単位で色/太さを上書き可能。手動編集されたグループは**会員関係をロック**、以降接触しても自動追加しない（手動追加/削除は可）。未編集グループは自動追従。
- 合成アルファ形状の**外側輪郭を先に描き**、その上へ個々の文字塗り・グランジを描画。グランジ穴がグループ外側輪郭を削らないよう別マスクで処理。グループ全体が外側輪郭の二重描画で太らないこと。
- 個別輪郭の幅は既定で**変形後の出力画像ピクセル基準で一定**。任意で文字変形と一緒に輪郭も拡縮するモードを追加。一体化輪郭は変形済みインクの合成形状から毎回生成する。
- グランジは文字の幾何変形の**後**に適用し、テクスチャ粒子サイズが倍率/せん断で不自然に伸びないようにする。一方、平行移動/回転では模様が文字に追従し、倍率/せん断時は粒の基準寸法を維持して再マップする。
- 共通 `inkSeed` は決定論的。通常の同一文字は異なる粒子パターン、複製文字は**元と同じ粒子パターン**で開始。パラメータ変更/保存/出力で勝手に種を変えない。
- 既存エフェクト・ブラー・歪み・文字太さ処理との合成順をテストで固定。マスクからの輪郭抽出ではグランジ穴による局所輪郭増殖を避ける。

**受入例 FR-03**: 3文字を大きく重ねて一体化輪郭を生成した際、文字間の内側輪郭は消え、外側輪郭が閉じて連続する。グランジ穴を増やしても外側輪郭は変化せず、編集/PNG出力の結果が対応する。

## 6. UI/UX・操作体系 [FR-04]

### 6.1 エディタ構成

- SFXオブジェクト選択→ダブルクリック/編集ボタンで文字単位モード。通常のレイヤー編集と視覚的に区別する。
- グリフ選択時に文脈対応プロパティパネルとコンパクトなクイックツールバーを表示。デスクトップ・iPad・iPhoneの狭い幅では同一機能を折畳み/ボトムシートで実現する。
- グリフ一覧には原文の字/文字インデックス/ロック状態/Z順/接続run/個別スタイルを表示。位置・角度・縦横倍率・せん断・ピボット/輪郭を数値変更できる。
- 位置ガイドとスナップは既定OFF。任意でON。キーボード矢印は1px単位で位置調整。編集ハンドルはズーム率/DPRで操作しにくくならないヒット領域を確保。
- 編集画面では文字・長音線・グループ・制御点間の選択優先を切替可能。全体レイヤーの誤選択を防止。

### 6.2 選択・操作

| 操作 | 動作 |
|---|---|
| 通常クリック/タップ | 最前面の文字/線を選択 |
| Alt+click | 同じ位置の背面候補を順送り |
| Shift+click、文字一覧 | 文字の追加/範囲選択 |
| 矩形左→右 | 全インク領域が矩形に含まれる文字を選択 |
| 矩形右→左 | インクと交差する文字を選択 |
| なげなわ | 実インク/線と交差する文字・線を選択 |
| ドラッグ | 文字または選択したグループを移動 |
| Ctrl+drag / Cmd+drag（デスクトップ実装に合わせる） | ドロップ位置へ文字複製 |
| Ctrl+D / 複製UI | オフセット複製。別途同座標複製あり |
| Ctrl+C/V、Cmd+C/V | フォーカスと選択内容に応じてSFX全体/文字群/ストローク/通常テキストを切替 |
| Esc | 文字編集中はドラフト取消。選択解除は文脈に応じて次段階 |

- タッチ：1本指は対象文字を移動、余白ではパン。2本指でキャンバス操作。手のひら/スタイラス・ペン入力は競合しないようPointer Eventsを利用。手のひら誤操作は可能な範囲で抑制。
- モバイル：大型ハンドル、長押し拡大ルーペ、数値入力と±1px微調整、スタイラス操作を提供。
- 制御点編集と幅点編集の誤動作を避け、ドラッグ中の操作説明・アクティブモードを明示する。

### 6.3 貼付け時の外観ルール

- 同一SFX内のコピー/複製は個別文字の変形・位置・スタイルを継承。
- **別SFXへ文字貼付け**：位置/変形を継承するが、**フォント・塗り・輪郭などの見た目は貼付け先SFXの設定**を使用する。選択中の文字があれば、その**直後に**本文へ挿入。文字未選択なら末尾。貼付け位置は基準文字付近へ配置、コピー集合の相対配置を保持。
- 外部アプリから受け取るテキストは**プレーンテキスト**として扱う。入力フォーム内のCtrl+C/Vは従来のテキスト操作を優先。アプリの既存ページ/レイヤー単位コピー経路を破壊しない。

### 6.4 画像範囲外の扱い

- **出力キャンバスは絶対に拡大しない**。画像原寸の幅/高さを維持し、はみ出した文字/線は画像境界でクリップする。
- 編集中に**リアルタイム警告のみ**表示。書き出し時の追加ダイアログは設けない。画面外にある文字/線の編集情報は保存し、キャンバス外から戻せる。
- 内部のSFX配置枠の拡張（§3）と、画像出力寸法の固定は別の概念として実装する。

**受入例 FR-04**: iPadタッチ・iPhoneで文字を選択/移動/数値調整できる。背面文字と一体化輪郭の選択が機能する。元画像1000×750pxで文字を境界外へ置いてもPNGは1000×750pxのまま。

## 7. デザインテンプレート・プリセット [FR-05]

### 7.1 デザインテンプレート

- 「SFXオブジェクトを複製」と「本文非依存のデザインテンプレート保存」を分ける。
- テンプレートに含める: 共通スタイル、文字配置の相対座標/重なり/スケール、SFXの幅/高さ・基準文字サイズ、線長/曲線/太さ・形状、seed方針。**本文そのものとページ絶対座標は含めない**。
- 文字数が異なる場合は、元文字列の相対インデックス座標から受け手へ補間適用。先頭/末尾の端点と方向を保ち、文字数1/0、改行、長音線の有無を処理する。
- `ー`用のストロークテンプレートは**受け手に `ー` が存在するときだけ**適用。存在しない場合に原文へ `ー` を勝手に追加しない。
- 適用モード: `すべて / スタイルのみ / レイアウトのみ`。本文とページ上の絶対位置は常に維持。
- テンプレートはブラウザ内・プロジェクト内で管理し、独立したJSONのインポート/エクスポートに対応。バージョン判定、壊れた/不正な値の検証を実施。
- インポートID/名前競合時は `スキップ / 上書き / 名前変更` の選択（既定**スキップ**）。組込プリセット保護と既存プリセット管理に整合させる。
- フォント欠損時は警告して **代替フォント選択またはフォントアップロード**へ誘導し、メトリクス/アタッチメントを再計算。黙って結果を確定しない。アップロードフォントの長期保存/再配布はライセンス規約に従う。

### 7.2 実装上の分離

既存の `src/presets.js` にある種類別プリセットと新規SFXデザインテンプレートは、用途・形式・管理画面を区別する。既存のプリセットの名前/ID/既定値を壊さない。テキスト置換に伴うテンプレート適用・ロック保持・seed再発行は同じ変換APIを使用する。

**受入例 FR-05**: 「ドカーン」用の密集文字デザインを保存し、本文 `ボコッ` を持つ別SFXへ適用して原文とページ座標を変えず相対的な配置とスタイルを再現。JSON再インポート後も同様。

## 8. ファイル互換・プロジェクトID・競合処理 [FR-06]

### 8.1 形式方針

- 現行の **`PROJECT_VERSION=13`** を基準に、本文と新フィールドを保存できる次版（通常は **v14**）へ更新。着手時に最新バージョンを確認し、衝突すればさらに次版を採用。
- `.serifu` **コンテナ版2は原則維持**。新しい `projectId`、`pages[].id`、SFX `lettering` をmanifestへ追加し、既存のbinary assetレイアウトを変更しない限りコンテナ版増分は不要。binary section追加が避けられない場合のみADRを作りコンテナ版を上げる。
- JSON編集データにも同等のフィールドを持たせる。画像は従来どおり `.serifu` に同梱し、データ単独で再編集可能。`.serifu`には復元用のブラウザ内5世代履歴を含めない（ユーザーが指定した自己完結した**現在のプロジェクト**を格納）。
- 旧コンテナ版1、現行コンテナ版2、JSON v1〜13、従来IndexedDBデータは読込可能とする。旧SFXは編集モードに入るまで旧レンダリングを維持。旧形式ロードで適切なUUIDを付与するが、旧ファイルの再読込のたびに既存IDと誤照合しないよう、ID欠損時の導入動線を整理する。
- 既存ページ・レイヤーのIDは再読込・コピー・履歴復元で用途に応じて引継ぎ/再発行を区別する。`normalizeLayer` が読み込むたびに新UUIDを振る既存コードの挙動を検証し、新形式では永続ID/グリフ編集対応が壊れないよう必要な修正を行う。
- フォント表示差は実装環境によるため、欠損フォントを通知して代替/アップロードを選ばせ、変更前のメタデータも適切に保持する。

### 8.2 IDとファイル競合（#108〜111）

| 操作 | プロジェクトID | 自動保存と履歴 |
|---|---|---|
| 通常の `.serifu` 書出し | 維持 | ブラウザ側は変更しない |
| 「別プロジェクトとして複製」 | 新規発行 | 新たな履歴開始。元は無変更 |
| 同一ID・同一内容のファイルを開く | 維持 | 競合確認は不要 |
| 同一ID・内容が異なるファイルを開く | ユーザーに3択 | `ファイル / 自動保存 / 別プロジェクト` |
| 「別プロジェクトとして開く」 | **読み込んだファイル側**へ新ID | ブラウザ側の元IDと履歴は維持 |
| 「ファイルの内容を開く」 | 維持 | ファイル状態に置換し既存5世代を維持。次の履歴生成タイミングで新世代を追加 |
| 「自動保存から再開」 | 維持 | ブラウザ最新成功状態を開く |

- 「内容一致」はファイル名・日時ではなく編集状態（画像/マスク参照、本文、レイヤー、設定等）の正規化比較で判定。UIの一時的な選択/スクロール/保存日時は比較対象外。大容量素材は保存済みハッシュ等を用いて再計算を抑制。
- 同IDファイルを読み込んでも、他タブが編集権を持つ場合は第97〜99問の排他規則に従う。
- 新ID複製時は物理画像Blobを可能なら共有し、論理プロジェクト/履歴は独立。GCは参照数・有効世代を見て実施。

**受入例 FR-06**: 同IDの古い `.serifu` を開くと3択、別プロジェクトなら新IDで元履歴が残り、ファイル内容なら現行を置換して履歴は残る。旧ファイルも従来のPNGに描画され、旧版読込でフォント/マスク/吹き出しを壊さない。


### 8.3 現行「編集データを読込」の追加動作と、新しい「プロジェクトを開く」の区別

現行 `src/app.js` は `projectInput` から読んだページを `pages.push(...loaded)` で**現在の画像一覧へ追加**する。この既存動作と、#109〜111の**プロジェクト単位で開く・復元する**動作を混同してはならない。

- 新たに `activeProject`（少なくとも `projectId`、ページ一覧、保存リビジョン、編集権、履歴ハンドルを持つ）というプロジェクトコンテキストを導入する。
- **「プロジェクトとして開く」**は現在のプロジェクトを切替/置換する操作であり、同じIDなら#109の競合判定を行う。読み込んだプロジェクトのページ一覧・ID・保存履歴が独立して整合する。
- **従来の「編集データを現在の画像一覧へ追加」**を維持する場合、取り込んだページは**現在のプロジェクトへ複製・インポート**として追加する。取込元の`projectId`と履歴を現在のプロジェクトへ取り込まない。ページID・レイヤーIDの重複を防止し、必要なIDは再発行する。
- ユーザーがどちらの動作を行うかUIで区別し、従来の「追加」が無言で「全置換」へ変わる回帰を禁止。履歴の対象は1つの`activeProject`全体であり、ページ単位のUndo/Redoとは別物。
- 既存の一括PNG/画像ページ移動・追加・削除/マスク素材参照は`activeProject`配下の操作として移行する。読み込んだ別プロジェクトの保存世代を、現在のプロジェクトの自動保存へ混ぜない。

**受入例 FR-06b**: 既存画像一覧がある状態で旧「追加」を使えば従来どおり画像が増え、同IDの別ファイルを「プロジェクトとして開く」と3択競合へ進む。それぞれでプロジェクトID、ページID、保存履歴の対応が正しい。

## 9. IndexedDB自動保存・履歴・素材共有 [FR-07]

### 9.1 保存ポリシー（#95〜96、#100〜107、#112〜113）

**保存系の2種類を明確に分離する。**

1. **最新状態（latest）**：編集の**確定後**に短い遅延で自動保存。操作が続く間はdebounceして書込みをまとめる。現行の定期自動保存（既定2分、設定0.1〜1440分）も維持し、未保存の確定済み変更があれば保存。IME入力途中やドラッグ途中、仮プレビューなど未確定ドラフトは保存対象にしない。
2. **復元履歴（history）**：**原則5分間隔**で編集済みの完全スナップショットを1世代追加。最大**5世代**。同じ状態の重複履歴は作らない。最新状態の保存回数と履歴作成回数は連動させない。

編集確定後のdebounce値は初期実装では **750ms程度の内部定数**を候補とする。これはユーザー決定値ではなく調整可能な実装定数であり、測定に応じてチューニングすること。最新保存の成功/失敗・保存中・最終保存時刻・保存後の変更ありはUIへ表示。保存失敗時は警告し、次回の保存トリガーで再試行。保存の成功を偽装しない。

### 9.2 スキーマ案（DB `serifu-editor-drafts` をv2から増分移行）

| ストア | キーの概念 | 内容 |
|---|---|---|
| `projects` | `projectId` | 名前、作成/更新日時、設定、最終編集タブの情報などのメタデータ |
| `snapshots` | `snapshotId` | 完全な確定済みプロジェクトメタデータ、ページ、レイヤー、素材参照 |
| `latest` | `projectId` | 最新の**正常保存済み** `snapshotId`、保存リビジョン/時刻 |
| `history` | `[projectId, createdAt, historyId]` | 復元用 `snapshotId` への参照（最大5件/プロジェクト） |
| `imageAssets` | `assetId` | Blob、mime、寸法、hash、サイズなど。複数プロジェクト/世代から共有可 |
| `maskAssetsV2` | `assetId` | 既存マスク素材のBlob・検証メタデータ。全世代参照可能な構造 |
| `locks` | `projectId` | 編集権所有タブID、lease期限、**単調増加fencing token** |
| 旧 `drafts`,`images`,`masks` | 既存キー | v2移行のため当面読込専用/保護。検証完了まで削除禁止 |

`imageAssets` は同一原本の変更がなければ画像を書き直さず、文字変更では `snapshots/latest` を中心に更新する。画像を差し替えた場合は新Blobを格納し、各世代が当時の素材IDを保持する。**マスク素材も同等に世代追跡すること**（歴史復元時にマスク欠損を発生させない）。画像のBlobを参照共有しても、論理プロジェクトの編集履歴は共有しない。

上記ストア名は実装案。索引とGCの負荷、Safari系IndexedDBの制約に合わせて適切に構造化してよいが、意味論は変更しない。

### 9.3 原子的保存・障害復旧（第113問 B）

- 新snapshotおよび不足する素材Blobを準備/検証し、同一IndexedDBの`readwrite`トランザクション内で不足素材登録・snapshot作成・参照チェック・**latestポインタ切替**を実行する。`oncomplete`までUIを「保存済み」にしない。
- 保存の途中/トランザクション中に例外・quota・タブ停止が起きたらトランザクションを中止し、**旧latestとその参照素材を残す**。不完全なsnapshotが`latest`として露出しない。
- 履歴5世代の輪番更新もトランザクションで実行。画像/マスク参照が成功しない履歴を「正常」として追加しない。
- 不要画像・不要snapshotの削除は参照到達性の確認後に行い、**新規保存の成功後**に不要なものだけGC。容量不足の自動削除を伴う再試行は禁止（#106）。`QuotaExceededError`をUIへ伝達する。
- サイトデータ削除・ブラウザのプライベートブラウズ・ストレージのユーザーによる破壊的削除に対して無条件の復旧を保証しない。`.serifu`書出しを長期バックアップ手段と明記。
- 全バージョンでserialize前に参照整合性を検証し、古い壊れたレコードでアプリ全体が起動不能にならないよう個別エラーとする。

### 9.4 5世代の復元ルール（#102〜105、#111〜112）

- 復元対象一覧に**保存日時**を表示し、5世代から選択。復元すると現在の編集状態（画像/マスク/テキスト/曲線/設定）を過去snapshotで**直接上書き**する。
- **復元直前の状態を自動退避しない**、比較プレビューも追加しない（#104 A）。復元前に未確定のテキストドラフトがあれば、通常の保存/取消ルールと整合する明示的なUIを使用し、黙って保存しない。
- 復元操作時に既存履歴5世代を**削除・変更しない**。復元された現在状態は最新状態への自動保存対象となり、**次の5分間隔の履歴作成タイミング**に新たな世代を加える。保存に伴い6世代目が作られたときのみ最古を削除。
- ファイルを優先して開いた場合も同じく旧履歴を維持し、履歴作成タイミングで新世代を追加する。復元操作で履歴を無秩序に増やさない。
- 画像の差替えをまたいで復元する場合は、当時の画像に戻す。参照が1件でも残る旧画像はGCしてはいけない。

### 9.5 容量不足・手動管理（#106〜107）

- 容量不足時は自動保存を止めて保存失敗を通知。**履歴を自動削除しない**。現画面の編集継続は可能だが「保存されていない変更がある」と表示する。
- プロジェクト一覧: 名前、IDの短縮表示、最終保存、容量推計、5世代の日時/概算サイズ。
- プロジェクト単位および世代単位で、明示確認後に**手動削除**。複数世代が参照する画像/マスクは維持。削除後に到達不能になった素材だけ回収。
- 削除前に「論理サイズ」と「実際に解放可能な推定サイズ」を区別。共有素材のサイズを重複して加算しない。Quotaのブラウザ推定値(`navigator.storage.estimate`)は概算と明記。
- プリセット/デザインテンプレートと自動保存履歴は別管理。自動保存整理でプリセット・別プロジェクト・既存 `.serifu` ファイルは消さない。
- 容量不足状態でも独立した `.serifu` 書出しが正常動作しうることを確認。ただしダウンロード先の空き容量やブラウザ制限は別エラーとして伝える。

### 9.6 v2自動保存からの移行

1. IndexedDBの**新バージョンへ増分アップグレード**。旧オブジェクトストアを削除/クリアしない。
2. 既存 `drafts.current` と画像/マスクを検証して、旧データに新しいプロジェクトIDを発行。現行版ではprojectIdが存在しないため、実行時の新規発行と旧保存との紐付けを明示。
3. 新スキーマへ書込後、スナップショットの参照整合性・復元可否を検証し、**新latestコミット完了を確認**。旧ストアは少なくとも移行中は保護。
4. 移行中断/容量不足/別タブによるDB versionchangeでも、旧ストアから再実行可能な**冪等処理**にする。多重コピーや二重履歴を作らない。
5. 現行 `restoreDraft` UIとの連続性を維持。履歴初回生成は旧データ移行時の扱いをADRに明記する。

**受入例 FR-07**: 画像Aの5世代がある状態で画像Bへ交換し、旧世代を復元するとAへ戻る。容量不足エラー後も直前の最新正常スナップショットと5世代が存在。編集確定を30秒間に20回行っても履歴は20世代にならず、原則5分間隔。

## 10. 複数タブ排他・編集権移管 [FR-08]

### 10.1 動作（#97〜99）

- 排他単位は **projectId**。同じプロジェクトを複数タブで開く場合、最初に編集権を取得したタブのみ編集可能。他タブは**閲覧専用**。
- 編集タブの正常終了（`pagehide`等）で編集権を解放し、異常終了ではheartbeat/lease失効を検知して回復する。正常終了通知はbest effortであり、タブクラッシュ等で検知に時間がかかることをUIへ表現。**手動の編集権譲渡要求は設けない**。
- 引き継ぎ先は**最後に実際に操作された閲覧専用タブ**を優先（#99 B）。ここでいう操作とはクリック/タップ/キー操作などの明示的なユーザー入力であり、heartbeatやバックグラウンド再描画ではない。同時刻競合は安定したタブIDで決着。
- 引き継ぎ後、タブは**最新の正常保存済みデータを再読込**してから編集を有効化する。終了前にまだ自動保存されていない変更の復元は保証しない。
- 自分以外が所有するプロジェクトは自動保存・手動保存（ブラウザ内のstate更新）・履歴削除などの変更系操作を禁止。閲覧専用画面は保存成功通知を受けて既存データを参照更新可能。ユーザーへの閲覧専用/編集可能表示を設ける。

### 10.2 実装上の排他保証

- `BroadcastChannel` は通知用途に利用可能だが**ロックの唯一の正本にはしない**。`navigator.locks` を利用できる環境での活用、非対応環境でのIndexedDBトランザクションによるcompare-and-swap/lease方式など、クロスタブ競合を防ぐ一貫した設計を採る。
- ロック獲得ごとに**単調増加fencing token**を発行。編集者が旧トークンのまま保存を送っても、**latestコミットと同じトランザクション内**のトークン検証で拒否する。
- 編集権失効後は旧タブの保存タイマー・deferred saveを中止。旧タブが復帰した際にも、自動的に編集権を奪わない。
- 複数タブが同時獲得、タブのクラッシュ直後、PCのスリープ復帰、長時間バックグラウンド、Safari/iOSのページ凍結をテスト対象とする。
- 既存 `storage.js` の`onblocked`・`onversionchange`に配慮し、DBアップグレード中の複数タブには安全な再起動/更新誘導を表示する。

**受入例 FR-08**: タブAで編集、B/Cで閲覧。Cが最後に操作されてAが閉じられるとCが自動で編集権取得。Bは閲覧のまま。Aが再開/復活しても旧tokenでは保存できない。同時に書込可能なタブが2つになる瞬間がない。

### 11.5 性能/品質

- インタラクション中は近似品質を使い、ドラッグ終了後に最終品質を再描画。測定対象/環境・平均/95パーセンタイル・文字数/画像サイズをベンチマーク記録。

## 13. 非対象・設計補足・実装判断の委任範囲

### 13.1 非対象

- 自動レタリングの機械学習モデル追加、生成AIによる任意の筆跡生成。
- 文字単位の遠近/3D透視変形（#53で対象外）。
- 効果音とは独立した装飾用の複製グリフ（複製は必ず本文へ反映）。
- 画像キャンバス自体のサイズ拡張、書出し時の追加確認ダイアログ。
- 複数タブでの共同同時編集、リアルタイムの複数ユーザー同期、クラウドストレージ同期。
- 5世代とは別の手動名前付き復元ポイント、復元前の比較画面、自動履歴間引き削除。
- SAM3モデル/バックエンドの変更、既存画像加工の仕様改変。

### 13.2 ユーザー要件を変えない実装裁量

以下は未決の要件ではなく、ユーザー方針の範囲内で開発者がADRに固定してよい技術パラメータ：debounceの短い時間、leaseの失効秒数、preview品質の低減方式、パス補間の数値解法、キャッシュ制限、内部DBストア名称/索引、プロジェクトハッシュの算出法、競合時の通知文言、スプラインの数値安定化の閾値。**いずれも採択済みの操作仕様や安全要件を変更してはいけない。**

### 13.3 主要な優先順位（衝突時）

1. 原文と文字編集の一致、データ損失防止、旧形式互換を最優先。
2. **出力キャンバス寸法固定（#79修正）が編集用外接枠の自動拡大（#13）に優先。**
3. **履歴は5分間隔（#112）が「保存のたびに履歴追加」と読める先行回答に優先。**
4. **ファイルを優先して開いても既存履歴維持（#111）、履歴復元でも既存履歴維持（#105）。**
5. **編集確定済みのみ保存（#95）**。保存やページ切替操作が本文確定を伴う場合は、まず正規確定処理を完了してからスナップショット取得する。
6. **新SFXのみに新描画アルゴリズムを適用**。旧SFXを意図せず再レンダリングしない。
7. **保存時のatomicity（#113）** と **旧タブ書込防止（#97〜99）** を同じ保存経路で保証。
8. ドキュメント・受入テストにない新機能はスコープを膨らませず、追加要望として別SOW/ADRで扱う。
