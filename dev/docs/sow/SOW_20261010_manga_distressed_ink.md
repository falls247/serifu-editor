## 1. 目的と完成状態

ユーザーが任意の日本語効果音（例：「ガッ」「ザザザ」「ドン」）に対し、添付参照画像に近い**擦り切れたインク／版ずれではないラフな印刷・ステンシル状の文字質感**を付け、個別のパラメータで調整できる機能を追加する。

完成状態では、太い字画の内部に細かい白抜け（厳密には透明な欠け）、方向性のある縦／斜めのかすれ筋、輪郭の細かな崩れ、文字周辺の少量のインク飛沫が同時に見える。見た目はユーザーが入力した文字・書体・文字色に従い、移動・回転・縦書き／横書き・保存・再読み込みでも変化しない。

**必須：単なるノイズテクスチャの重ね表示、ぼかし、フォント変更だけで完了としない。**

### 1.1 添付画像の観察と再現境界

| 観察できる視覚要素 | 必須の挙動 | 対象外／注意 |
|---|---|---|
| 暗い紺色の太い文字・大胆な手書き形状 | 既存の任意フォント／文字色を保持し、専用プリセットから紺色を選べる | 文字の形状そのものを特定フォントに固定しない |
| 太線の**内部にランダムな細い欠け** | 字画の実ピクセルのアルファを落とし、元画像が見えるようにする | 欠けを白色で塗りつぶさない |
| 主に縦方向の長短の擦れ筋、裂け目 | 方向／長さを調整できる非一様な筋状マスク | 一定周期の縞模様・単純な矩形列にしない |
| 文字輪郭の不連続・小さな欠損 | 文字形状に沿って局所的にチップ状の欠けを作る | 輪郭全体を単純な均一ぼかしにしない |
| 文字近辺の小さなインク粒・飛沫 | 字形周辺に低密度の飛沫を追加する | 字の外側の任意の遠方に無制限に撒かない |
| 紺色の文字と赤／紺のコマ境界、淡い背景 | **文字インクのみに質感を適用**。元画像にすでにある境界・背景は書き換えない | 赤青のコマ罫線、背景紙色を自動生成する機能ではない |

参照画像から抽出できる色の代表値は概ね文字インク `#14305F`、背景 `#ECE5DF` 付近（画像の圧縮・画素差により概算）。**色そのものはユーザー指定を優先**。模倣に使うなら専用プリセットだけの既定値として設定する。

### 2.1 既存の「掠れ」との差分

- `roughness`：輪郭付近の荒れ。
- `dryInk`：主に線状の筆の掠れ。
- `brushTails`：字形のハネや払いの追加。
- **新機能 `inkTexture='grunge'`**：字画全体に対する異なるスケールの欠け、方向性のある大量の細い擦れ、輪郭チップ、字外への局所的な飛沫を一つの表現として制御。

既存の3パラメータは残し、新機能はそれらを自動的に上書きしない。ただし極端な併用では文字判読性が下がるため、専用プリセットは3パラメータを低めに設定し、新機能側で見た目を作る。

## 3. スコープ

### 3.1 必須（MUST）

1. `sfx` レイヤーに独立したインク質感モードと強度・擦れ筋・飛沫・seedを追加する。
2. 実際の文字マスクに作用する、透明な欠け／擦れ／輪郭欠け／近傍飛沫を再現する。
3. 縦書き・横書き、各書体、文字色、太さ、回転、歪み、先細り等と両立させる。
4. `inkTexture='none'` では**既存の描画を変更しない**。
5. 文字内の欠けが白縁・影の下地で埋まらないように、質感ON時の合成を設計する。
6. 同一seed・同一レイヤー入力・同一フォントの再描画結果を固定し、同じ文字が複数出る場合は文字ごとに異なる模様を持てるようにする。
7. UI、組み込みプリセット、ユーザープリセット、コピー、Undo/Redo、保存、復元、PNG出力を整合させる。
8. 旧JSON／旧 `.serifu` ファイル、一時保存、既存プリセットの読み込みを壊さない。
9. 単体・ブラウザ・PNG・Workerの検証を追加し、既存テストを通す。
10. 実装判断のADRと利用者向け操作説明を更新する。

### 3.2 対象外（MUST NOT）

- 赤／青のコマ線・背景色・紙テクスチャの自動生成／変更。
- 元画像の画素を破壊的に編集する処理、外部への画像送信、AI画像生成API。
- ベクターパスの手書き編集、ペンタブのブラシエンジン、新フォントの追加。
- 台詞 `dialogue`、キャプション `caption`、吹き出し `balloon` への質感機能展開（将来拡張可）。
- 全字形への物理的な「本物の印刷シミュレーション」や、参照画像とのピクセル一致。
- WebGPU／WebGLへの全面移行、常時動作するアニメーションノイズ。

## 4. UIとデータ契約

### 4.1 追加データモデル

`kind==='sfx'` 専用のフィールドとして以下を定義。名前・範囲は仕様固定。JSON表記とUI表記を区別する。

| フィールド | 型・範囲 | 新規作成時の既定 | 意味・UIラベル |
|---|---|---|---|
| `inkTexture` | `'none' \| 'grunge'` | `'none'` | インク質感：なし／かすれ印刷・荒れインク |
| `grungeAmount` | number, `0..100` | `65` | インク欠け・輪郭荒れの強さ（%） |
| `scratchLength` | number, `0..100` | `55` | 擦れ筋の長さ（%）。0で方向性のある長い筋を無効化 |
| `scratchAngle` | number, `-180..180` | `90` | 擦れ筋の方向（°）。字形ローカル座標で0=右、90=下 |
| `spatterAmount` | number, `0..100` | `40` | インク飛沫の量（%）。0で飛沫なし |
| `textureSeed` | uint32, `0..4294967295` の整数 | `inkSeed(id + ':texture')` | 質感模様の固定seed。複製時は維持し、再生成操作で変更 |

- 全フィールドは**モードOFFでも保持**。OFF→ONで以前の値を復元。値は100%を超えないようUI入力でclampし、ファイル読込では非有限値／範囲外値を拒否する。
- 既存レイヤー／v1〜v6読込でフィールドが**存在しない場合**は `inkTexture='none'` と各既定値で補完し、見た目を維持する。既存レイヤーの `textureSeed` 初期値は保存済み `id` があれば `inkSeed(id + ':texture')`、なければ `inkSeed(text + ':texture')` で安定生成する。`normalizeLayer()` が既存IDを作り直す経路では、正規化前の入力情報からseedを先に確定すること。
- `textureSeed=0` は正常値。`|| default` で0を潰さず、`??` を使う。
- 新規レイヤー生成は通常の `inkTexture='none'` とし、既存効果音の初期見た目を変えない。
- **SFXの `outline=0` を許可**し、輪郭を完全に無しにできるようにする（現行は最小1）。台詞の最小輪郭1は維持する。数値UI、検証、プリセット適用、コピー／拡縮を同時変更。SFX用インク質感プリセットは `outline=0` を使用。
- `grungeAmount=0` / `scratchLength=0` / `spatterAmount=0` の個々のゼロ動作を単体テストする。`inkTexture='grunge'` でも3強度が全て0なら字形ピクセルは効果OFFと一致（輪郭0指定以外の条件を同じにする）。

### 4.2 UI要件

既存の各効果音カードに、従来の「漫画エフェクト」と**独立**した「インク質感」選択を設ける。選択肢は「なし」「かすれ印刷・荒れインク」。

- モードが `grunge` のときだけ、上記4種のパラメータ（強さ・擦れ筋長さ・方向・飛沫量）と「模様を再生成」ボタンを表示する。入力は `data-field` 方式を利用し、`EFFECT_LIMITS` と整合させる。
- `textureSeed` を入力するテキスト欄は不要。再生成ボタン押下時、seedを決定的な式で次値へ更新する（例：`(Math.imul(oldSeed,1664525)+1013904223)>>>0`）。各押下は**1回分のUndo**として記録。再生成後のPNGは変わるが、保存後・再起動後は変わらない。
- 強さや角度の変更時は従来どおりライブプレビューを更新する。IME入力、選択、他のカードの編集に干渉しない。
- 詳細設定が閉じていても「インク質感がON」であることを識別できる。
- ヘルプに「欠けは透明で元画像が透ける」「角度90°は下方向」「既存の『筆の掠れ』と併用可」を明記する。
- PC幅と狭い画面幅で入力欄がはみ出ないこと。SFX以外には表示しない。

`presets.js` に次のプリセットを追加する。既存の組み込み／ユーザープリセット、既定プリセットID、保存済み設定は変更・削除しない。

| 項目 | 指定 |
|---|---|
| ID | `sfx-grunge-print` |
| 表示名 | `かすれ印刷・荒れインク（参考画像風）` |
| 種類 | `sfx` |
| `effect` | `'none'`（集中線／立体影なし） |
| `inkTexture` | `'grunge'` |
| `color` | `'#14305f'`（プリセット選択時のみ） |
| `outline` | `0` |
| `font` | `'comic'` を推奨初期値。利用者が変更可能 |
| `grungeAmount` | `70` |
| `scratchLength` | `60` |
| `scratchAngle` | `90` |
| `spatterAmount` | `35` |

プリセット適用後も入力文字列とレイヤーIDは維持。新プリセット適用時の `textureSeed` は**レイヤー固有の既存seedを保持**し、ユーザープリセット保存時にseedを記録して全レイヤーを同じ模様にしてはならない。具体的には `textureSeed` を書式プリセット対象外とする。`glyphSeed` も既存運用を維持する。

## 5. 画像処理アルゴリズム

### 5.1 選定する方式

| 候補 | おすすめ度 | 評価 |
|---|---|---|
| **A. 既存Canvasのグリフ・アルファマスクを加工する** | ★★★★★ | 既存 `ink.js`・`renderer.js`・Worker・PNGと共通化でき、透明な穴・seed固定・細かな制御に最適。CPU時間には注意 |
| B. PNGノイズ素材を文字の上に合成する | ★★☆☆☆ | 初期実装は簡単でも、反復感・解像度依存・色抜け・ライセンス・プリセットの一貫性が問題 |
| C. WebGL／WebGPUシェーダーに置き換える | ★★☆☆☆ | GPU高速化の余地はあるが、全ブラウザ対応、Workerと共通描画、フォールバックの難易度が高い |

**採用：A。** 新規の実行時依存は原則追加しない。純粋関数として `ink.js` に処理をまとめ、見た目と計算量をテスト可能にする。

### 5.2 推奨関数インターフェース

```js
// ink.js（関数名はこの案を標準とする）
export function printDistressMask(source, width, height, options) {
  // options = { size, grungeAmount, scratchLength, scratchAngle,
  //             spatterAmount, seed }
  // source: Uint8ClampedArray(width*height), 0..255
  // return: { body: Uint8ClampedArray, speckles: Uint8ClampedArray,
  //           knockout: Uint8ClampedArray }
  // 入力sourceは変更しない。描画APIやグローバル状態を参照しない。
}
```

- `body`：元の文字内部で残ったインク量。**入力の字画外では基本ゼロ**（外側の付着は別のspecklesへ）。
- `speckles`：字画付近の孤立したインク粒。入力マスクが完全ゼロ、または空白書記素なら完全ゼロ。
- `knockout`：除去した字画内部のアルファ。描画時に下地の白縁／影が穴を埋めないために使う。`source - body` のクリップ済み差を基準とする。
- これらを一枚の画像に統合する実装も可。ただし**穴の透明性と字外飛沫**を個別にテストできる内部構造を維持する。

### 5.3 マスク生成要件

1. **多階層の欠け**：単ピクセルの孤立欠け、小さな塊、輪郭から内側に入り込むチップ状の欠けを混ぜる。局所的に密度差のあるノイズとし、格子／等間隔の周期模様を避ける。字画外に白い模様を描かない。
2. **方向性のある擦れ筋**：太い字画の中を通る短／中／長の裂け目を、`scratchAngle` 軸に沿って生成。開始点・幅・長さ・揺れ・端の先細りをseedでばらす。全ストロークが同じ長さ／平行線密度にならないこと。`scratchLength=0` で長い筋だけを無効化し、細かな欠けは残せる。
3. **輪郭チップ**：アルファの境界付近だけに不規則な凹みを作る。`roughness` の既存処理と異なり、本文の欠け生成と同じ局所密度を共有して質感に連続性を持たせる。
4. **飛沫**：字画境界に近い位置へ、小さい点や2～3点のクラスターを置く。半径・距離・密度を文字サイズに比例させる。文字から離れたコマの赤い罫線や背景全域に拡散させない。
5. **強さの単調性**：seed・元マスクが固定なら、概ね `grungeAmount=20 < 50 < 80` の順で字画内の欠損面積が増える。内部でランダム点を毎回引き直すのではなく、固定した候補と閾値によって強度を制御することを推奨。
6. **強い設定での可読性**：新効果のみを100%にした場合でも、代表的な100～200px日本語太字で元の字画のアルファ質量の**少なくとも55%を残す**（目標）。極細フォント、既存`dryInk=100`との併用、太さの大幅なマイナスはこの保証外。極細字画には擦れの最小幅と欠損密度を制限する。
7. **画素スケール**：筋幅・飛沫径は `size` を基準に算出し、品質制限で字形Canvasを縮小する場合は、同じ縮小率を適用する。プレビュー拡縮だけでノイズ密度が変わらない設計。
8. **空白／記号**：スペース・改行・描画されない字形から飛沫を生成しない。句読点等の小さい文字は欠け／飛沫量を自動抑制し、縦書き句読点の右上配置は維持。
9. **ランダム性固定**：`Math.random()`、`Date.now()`、レンダリング時に更新されるseedを禁止。`textureSeed`・書記素インデックス・文字コードから32bitのサブシードを導出（例：FNV-1aや既存`inkSeed()`とのmix）。同じ「ザ」が3回並んでも、インデックスごとに違う模様。Undo・複製・保存・Workerで同じseed。
10. **計算量上限**：字形画像全走査は原則 `O(width*height)`、マーク追加は生成数と筋長の合計に比例。マーク生成数／筋長／外側距離／一時配列の上限を明示し、巨大サイズや極端な変形で無制限ループを起こさない。既存200万画素の中間字形上限と500万画素キャッシュ上限を守る。

### 5.4 合成順序と透明度（特に重要）

推奨経路：

```text
文字（フォント・文字方向・句読点補正・書記素単位）
    -> アルファ字形取得／サイズ変形・歪み
    -> インク太さの拡張・収縮
    -> 既存 roughness / dryInk
    -> 【新規】printDistressMask：内部欠け／方向擦れ／輪郭欠け
    -> 既存 brushTails の追加（必要なら順序調整し一貫性を保つ）
    -> 【新規】飛沫アルファの追加
    -> 文字色・白縁・影の合成（穴を再充填しない）
    -> 既存blurX / blurY / blur / motionBlur
    -> 回転・配置・背景画像との合成
```

合成時の義務：

- **質感ONかつ `effect='none'`、`outline=0`、各blur=0のとき、欠け部分の最終グリフアルファは0**。白の「かすれ風ペイント」ではないことを元画像上で証明する。
- 現行 `warpedGlyph()` は白い `border` をグリフ本体の下まで塗る。`body` だけのアルファを欠かしても白地が露出する問題がある。質感ONでは**輪郭リングを処理前の太さ調整済み字画の外周に限定**するか、既存 `dryInk` の欠けも含めた `knockout` により一時サーフェス内だけを `destination-out` すること。`effect='none'` + `outline>0` でも欠けが白く埋まらないこと。
- 影／ブラーを同時有効にした場合は、ブラーが欠けを意図的に滲ませること自体は可。ただしblur=0のときの完全な透過を壊さない。必要ならグリフ内の穴の合成と残像をレイヤー化する。元画像のCanvasへ直接 `destination-out` して背景画像そのものを消さない。
- 飛沫は既存 `l.color` を使用する。白縁がある場合、微細な飛沫を太い白縁で塗りつぶさず、基本的に**飛沫は縁なし**で合成する。
- `inkTexture='none'` のコードパスでは輪郭／影の描き方を既存と同一に保ち、回帰を避ける。

### 5.5 文字変形・座標と再現性

- `scratchAngle` は**字形ローカル座標**。レイヤー `rotation` の変更でエフェクトも文字と一緒に回り、設定値は変えない。縦書き・横書きで突然90°変化させない。
- 既存 `verticalRotation()` による長音記号等の回転には、字形の最終マスク座標と同じ座標系を適用する。
- `textGlyphs()` の `index` を `warpedGlyph()` に渡す。キャッシュキーへ `textureSeed`／`index`／`inkTexture`／4つの数値を入れる。欠損値はモデル正規化後に既定へ揃える。
- 既存 `glyphSeed` は文字ばらつき用。新 `textureSeed` と混同・上書きしない。別のseedで質感だけを再生成できるようにする。
- 色・輪郭・書体・サイズ・字形変形が変わる場合のキャッシュ更新を確認。ページを行き来しても模様の位置が揺れない。
- 既存の150～200万画素級の字形縮小とCanvasの透明ピクセルを考慮し、細線がすべて消えないようにする。

## 6. 保存形式・互換性・コピー

### 6.1 バージョン運用（推奨決定）

**プロジェクトモデル版6 → 7へ更新**する。理由：旧アプリが同じversion 6のファイルを読み、未知の質感フィールドを黙って捨てる事故を避けるため。互換に必要な作業を省略しない。

- `model.js`：`PROJECT_VERSION=7`。`normalizeLayer()` はv1～v6のSFXに欠損値を補完し、v7の指定値は厳格検証。既存モデルのcaption/balloonを維持。
- `project-io.js`：JSON出力は `version:7`、読込は1～7。高速 `.serifu` の**コンテナ版は1のまま**、manifestの `projectVersion:7` とし、旧 `projectVersion:6` と新7の**両方を読める**こと。magic・バイト列・アセット格納ルールは変更しない。
- `app.js` と関連する読込／復元／検証経路の `version===6` / `<=6` / 固定文字列を全検索し、v7でも通す。v1～v6ファイルを読んだ後に保存するとv7へ移行。
- `storage.js` のIndexedDBデータベース版1は、スキーマ変更がない限り変更不要。復元時のレイヤー検証だけv7に対応。
- 旧アプリへのv7読込互換は保証しない。「新しい編集データを旧版アプリで開かない」注意をREADMEに追加。古いJSONの読込互換と混同しない。

### 6.2 操作ごとの振る舞い

| 操作 | 必須結果 |
|---|---|
| レイヤー複製 | 質感・seedをそのまま複製。同一模様になることは仕様。再生成で個別変更可 |
| 単体コピー／ペースト | すべての設定とseedを保持。コピー先の解像度に応じる既存の文字サイズ調整は維持 |
| 画像単位の一括コピー／ペースト | 同上。プリセットIDの既存ポリシーを維持 |
| Undo / Redo | 質感モード・数値設定・再生成seedが編集履歴へ戻る。描画も一致 |
| ユーザープリセット | モード・強度・方向・色・輪郭を保存。**textureSeedは保存しない** |
| デフォルトプリセット | 保存済みの既定IDを勝手に新プリセットへ変更しない |
| JSON／ `.serifu` | 7として保存、旧1～6から読込。新フィールドを欠損させない |
| IndexedDB一時保存 | 復元後に質感とseedを保持 |
| PNG単体／一括保存／編集済みのみ | プレビューと同じ描画。元画像・順序・連番・ZIP代替保存の意味は維持 |
| 編集済み判定 | 質感変更だけでも `edited=true`。Undoで初回の変更を完全に戻せば既存ルールに従う |

## 7. 性能・メモリ・安全性

- 追加処理はCPU Canvasを基本とし、既存 `image-worker.js` のPNG出力でも共通関数を使用。非対応ブラウザの既存フォールバックも維持。
- 目標：標準シナリオ（画像2000×3000、SFX 5字×10レイヤー、size 100px、参考プリセット）で、**質感OFFに対して初回描画時間の増加は2倍以内、キャッシュ後の再描画は1.2倍以内**を目安とする。同一マシン・ブラウザ・字体・画像・ウォームアップ条件で10回以上測定し中央値とP95を報告。達成できなければ未達として原因と最適化案を記載（数値は設計時の目標であり現時点の計測結果ではない）。
- キャッシュ上限は現状の500万字形画素相当を超えない。**字形の3マスクをキャッシュに永続保持しない**。最終サーフェスを主キャッシュとし、中間配列を描画後に解放。必要なら実バイト数見積りも記録。
- `export-cache.js` の `RENDER_VERSION` を更新して、古いPNGキャッシュと描画結果が混在しないようにする。
- パターン生成はDOM／ネットワーク／ファイル参照無しで動く。画像サイズ上限と条件分岐で巨大配列・無限ループ・メインスレッド長時間停止を避ける。
- UIで不正な数値・空欄・小数を入力しても `NaN` を保存しない。モード値を動的HTML文字列に連結しない。新しい画像・フォントを外部ロードしない。
- 実装前後のベンチマーク結果は `dev/docs` に追記し、品質と性能のトレードオフが発生した場合はADRへ記録。

## 9. 受入条件（Acceptance Criteria）

次の条件をすべて満たして完了。主要ケースは**自動テスト + 実ブラウザの画像確認**を組み合わせる。色や字形の見た目は参照画像と「質感カテゴリが一致する」ことを人が確認し、厳密なピクセルコピーは要求しない。

| ID | 受入テスト | 合格条件 |
|---|---|---|
| AC-01 | `inkTexture='none'`、同一レイヤーの改修前後の描画比較 | 既存効果・縁・文字のピクセル差なし（同一ブラウザ・フォント条件） |
| AC-02 | プリセットで太い「ガッ」「ザザザ」を配置 | ①字画内部の不規則な透明穴 ②方向性のある長短擦れ ③輪郭欠け ④字外の少量の飛沫が判別可能 |
| AC-03 | 背景を市松模様・写真・赤青罫線にした上で穴部分を観察 | 色の白塗りでなく、穴から背景が見える。元画像は非破壊 |
| AC-04 | `effect='none'`、`outline=0`、blur=0で1字を描画 | 欠けの最終アルファ0、飛沫は文字色。白い塗り残し／縁取りなし |
