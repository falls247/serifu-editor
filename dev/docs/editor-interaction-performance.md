- 日付：2026-10-17
- 状態：実装・統合検証完了。文字サイズ70→81の元事象は未再現。
- 比較元：`c53be9c`。調査時`0f3ed1d`からアプリのコード変更はない。

## 描画処理の改善

輪郭の膨張・収縮とインクの太さ調整で使う`extremeMask()`は、透明な余白を含む中間Canvas全体を2方向に走査していた。非ゼロ画素の矩形を求め、必要な効果余白を含む範囲だけ走査するようにした。出力配列の寸法、画素位置、効果のseed、描画品質は維持する。

`adjustInkThickness()`の小数補間では、2つの半径に共通する入力範囲を再利用する。透明な配列、画像端、正負・小数の太さ、画像より大きな半径について、変更前の演算と配列を比較する。

グリフキャッシュの保持上限は従来の5,000,000画素を維持する。`glyphCacheStats()`で保持件数・画素数・hit/miss・追出し件数を読み取れる。測定のために上限を広げない。

## 描画単体の計測

WSL2、headless Chromium 141.0.7390.37、1600×1100、同じローカルフォントを使用。フォント準備後、キャッシュ消去後の描画を5回、1回描画してから消去しない反復を5回測定した。時間は共通`draw()`の処理であり、プリセット変更イベント全体の時間ではない。

| 条件 | 変更前の中央値 | 変更後の中央値 | 短縮率 |
|---|---:|---:|---:|
| 1200×900、84pxのSFX、毎回キャッシュ消去 | 126.7ms | 88.5ms | 30.1% |
| 元画像3000×2000・Canvas1400×933、280pxのSFX、毎回キャッシュ消去 | 1107.1ms | 618.5ms | 44.1% |
| 同じ大型SFX、キャッシュ消去なしの反復 | 1159.0ms | 605.7ms | 47.7% |

CPUプロファイルの`extremeMask()`自身の時間は、小規模53.38→7.46ms、大型615.53→69.46ms。プロファイラー付き単回測定であり、表の中央値とは分けて扱う。

大型条件では8文字を保持しきれず、保持4件・約494万画素だった。準備の1回と計測5回を含む統計はhit 0・miss 48・追出し44。したがって反復でも字形生成が走り、キャッシュ消去なしという条件だけでは字形が再利用される保証はない。大きいSFXで約0.6秒の同期描画が残る。

## 描画一致の検証

- 変更前`c53be9c`のrendererとinkを独立した参照モジュールとして保持し、現在のinkへ参照先が混ざらない状態で10条件の画素一致を確認した。
- 既存の旧レタリング描画24条件、原文インデックス4条件も確認した。
- 縦横、正負のインク太さ、方向別ブラー、印刷かすれ、ブラシ質感、文字単位編集を含む。参照fixtureが`c53be9c`の原本と一致することも確認した。

Node試験は43ファイルを確認した。41ファイルは通常のサンドボックス内で成功し、ローカルHTTPサーバーを使う`dev-launcher`と`sam3-proxy`は制限外で再実行して3試験成功。最初の`npm test`の終了コードは1だったため、単一実行ですべて成功した記録とは区別する。

`renderer.test.mjs`の吹き出しクリップ期待は変更前でも失敗した。既存ADR-0030に合わせ、本文を形状でクリップしないことと全文字を描くことの両方を検証する期待へ更新した。最適化に合わせて参照画素を変更したものではない。

## プリセットとページ表示

名前付きプリセットの適用は全4種類で既存カードDOMを保持し、共有コントロール・対象カードの設定・当該種類の既定選択を同期する。UIと寸法の更新から暗黙に描画しない経路を設け、変更の確定後にLIVE PREVIEWを1回描く。プリセット候補の追加・上書き・削除など一覧が変わる操作は、従来どおり必要な全体更新を行う。

表示範囲を切り替える場合は、並び順を維持する軽い行の枠を用意し、選択ページの画像と編集UIを先に準備する。他の行の重い準備はタイマーで1ページずつ進める。範囲の切替で準備世代を更新し、画像読込み完了時は行とマウントtokenを確認する。別ページへ移った後に古いCanvasへ描かず、範囲外の画像・Canvasの解放は維持する。

SAM3ドラフト破棄は、処理の取消・候補解放・UIリセットとプレビュー描画を分離した。ページを離れる際は破棄のための旧Canvas描画を省き、同じ表示範囲に残る旧ページには選択表示を更新する描画だけ行う。SAM3 UI初期化でも、呼出し側で行う初回描画と重複しないようにする。

段階的な準備の検証では、未準備の行にある数値欄がフォーカスを受けると、準備中のDOM移動によるblurが古い入力値をモデルへ保存する経路を再現した。準備前の入力値確定を抑止し、モデル値37に対して古い入力値81を置いた条件でも37を維持する回帰を追加した。準備済みページのアンマウントでは、フォーカス中の入力を確定してから準備状態を解除し、従来の入力確定を保つ。今回の表示準備変更に伴う不具合への対策であり、下記のユーザー報告と同じ原因とは扱わない。

未準備ページから「100%」を開く場合、空の画像srcに対して原寸プレビューのdecodeを始める失敗も再現した。ページの選択・準備を先に行ってから既存のプレビューを開く順序へ変更し、画像の再準備後に320×240pxの原寸Canvasが表示されることを確認した。追加のdecode待機や画像保持は導入していない。

下書き復元の既存ブラウザ試験では、時計を停止したまま周辺ページの入力欄を即時に読むと空配列になった。対象のプレビューへフォーカスして準備する操作を追加し、コピー内容の独立性を検証する期待値は維持した。

## 文字サイズ70→81

報告された「プレビューで選択しただけで70→81」は未再現。通常選択、微小なpointermove、文字単位編集への移行・クリックで、対象SFXのモデルsizeが変化しない回帰試験を追加した。別レイヤーが選択された際に共有サイズ欄がそのレイヤーの値へ切り替わることと、同じSFXの値が書き換わることを区別した。

原因未確認のまま比率プリセットを固定70pxへ変更していない。具体的なクリック位置、選択先レイヤーID、個別文字編集状態、モデル値の同時記録は継続調査項目。

原寸プレビュー試験では、既存の多角形頂点数`polygonCount`を整数フィールドの検査一覧に追加した。ショートカット試験でも、既存の形状選択肢`polygon`を期待する一覧へ追加した。いずれも変更前`c53be9c`で同じ失敗を再現し、ADR-0029の多角形仕様に期待を合わせた。原寸プレビューの検査や、形状巡回・Undo/Redoの検査は維持した。

## 操作全体の変更前後比較

整備した`editor-interaction-benchmark.mjs`を変更前`c53be9c`と変更後へ順番に実行した。1440×1000の隔離Chromium 141.0.7390.37を使い、画像・書式・字形／質感／ブラシ／形状のseedを固定した。他のブラウザ試験とは並行実行していない。

fixtureは51ページ。1ページ目は900×600px・4種類のオブジェクト（SFXは文字単位編集データあり）、2〜50ページは320×240pxの軽いセリフ、51ページ目は3000×2000px・280pxのSFX。立案時の1200×900px・6ページ48オブジェクトとは別の再現fixtureなので、立案時の213／351msと以下を直接比較しない。

プリセットは対象オブジェクトの選択とselectへのフォーカスを計測前に済ませる。冷条件は各回直前に`clearGlyphCache()`、反復は直前の適用後にキャッシュ消去なし。SFX以外も最初の適用を反復5回の集計へ混ぜない。

| SFX・キャッシュ消去後の同期適用 | 5 | 158.8ms | 213.9ms | 100.9ms | 117.7ms | 36.5% |
| SFX・反復の同期適用 | 5 | 55.4ms | 90.7ms | 13.0ms | 14.7ms | 76.5% |

| 吹き出し・反復の同期適用 | 5 | 81.6ms | 112.2ms | 15.5ms | 16.6ms | 81.0% |

SFX冷条件の最大は213.9→117.7ms、戻りの最大は2970.8→470.6ms。SFXの読み込み後最初の適用（n=1、手動キャッシュ消去なし）は197.1→126.3msだった。中央値の比較と単回の初回値を分ける。ページ選択は手動キャッシュ消去をせず、初訪と再訪を含む同じ5往復を比較した。

フォーカスを保持した条件のプリセット描画数は3→1回、元のカード4件の保持は0→4件。変更後は全4種類でカード削除イベント0、4件のDOMを維持した。操作中のフォーカス復元などを含むため、初期調査の2回描画という値と計測条件は異なる。

ページ選択の時刻は`clearRect`の開始ではなく、テスト時だけ応答へ注入する`drawPage`ラッパーで描画完了を記録した。全10遷移で2 RAF後までの対象描画は1回。連続選択は最新の001ページで落ち着き、その後に旧051ページが描かれないことを確認した。

SOWの暫定30%短縮目標を、上記の同条件比較では達成した。大きいSFXの表示に約0.65秒、戻りに約0.44秒の待ちは残る。GPU描画への移行やキャッシュ上限の拡張は行っていない。実機ブラウザ・異なる画像や書式での待ち時間は別に確認する必要がある。

生データは`/tmp/serifu-seeded-before/editor-interaction-benchmark-1792195811689.json`と`/tmp/serifu-seeded-after/editor-interaction-benchmark-1792195870821.json`。一時ファイルは消えるため、上の条件・集計と再現スクリプトを継続検証の基準とする。

## 再計測

```bash
npm run test:editor-interaction
npm run benchmark:editor-interaction
npm run benchmark:glyph-render -- --profile
```

描画単体の比較元を切り替える場合は、同じスクリプトで`SERIFU_GLYPH_BENCH_ROOT`へ比較元のフロントエンドを指定する。比較用ディレクトリには`server.mjs`、`src/`、HTML/CSS、同じフォントを用意する。操作ベンチと描画単体ベンチを同時実行せず、初回・キャッシュ消去・反復の条件を揃える。

`SERIFU_PROFILE_ROOT`で操作ベンチの比較元、`SERIFU_BENCH_SAMPLES`で試行数（既定5）、`SERIFU_BENCH_OUTPUT`で結果JSONの保存先を指定できる。

`SERIFU_BENCH_PRESET_FIXTURE=small`で1200×900px・1ページ4個、`dense`で同寸法・6ページ48個を測る。未指定なら上記の51ページの移動と4種類のプリセットを測る。例：`SERIFU_BENCH_PRESET_FIXTURE=dense npm run benchmark:editor-interaction`。
