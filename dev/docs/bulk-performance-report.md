# 一括処理の実装・検証報告（2026-10-10）

対象：[SOW](sow/SOW_20261010_bulk_performance.md)、[採用ADR-0010](adr/0010-bulk-processing-and-progress.md)。作業ブランチは `feat/bulk-performance`。コミット・push・公開は未実施。

## 実装

- 共通の操作ID、段階、確定件数、成功・失敗、経過時間、中断ボタンを追加。段階内の進捗を100ms間隔に集約し、段階・終了状態を即時通知する。通常ダウンロードは開始までを確認し、ディスク保存完了とは表示しない。
- 画像準備、長辺320pxのWebPサムネイル、共通 `draw` によるPNG生成を画像Workerへ移した。Workerは初期2個、4件以上の読込中だけ最大4個、PNG生成時は2個。稼働概算256MiB、結果待ち2件・64MiB、字形500万画素、PNG LRU128MiBを上限にする。巨大な単一画像は単独処理し、キャッシュ容量を超えるPNGは記憶しない。
- PNG/JPEG/VP8Xの寸法をヘッダで見積もる。未知の形式は全予算を予約して単独処理する。元画像Blobは保持し、全件のデコード結果は保持しない。ImageBitmap、Canvas、サムネイルObject URLを解放する。
- 画像追加は候補順を固定して20件ずつ準備・表示する。採用済みページの編集と表示範囲移動を許可し、追加・削除・順序変更・保存を制限する。中断時は採用済みページを残す。編集データ読込と復元は全件の検証・準備後に一覧へ反映する。
- PNG生成とwriterを重ね、close成功後に保存枚数を加算する。対象ページ・レイヤー・順序は開始snapshotを維持する。部分保存は全体の未保存状態を解除せず、中断・失敗時にフォルダとPNG枚数・編集データの有無を残す。
- 描画入力による容量制限付きLRUを導入。本文・配置・効果・書体・元画像の変更は別キーになり、ページ番号・選択・表示倍率はキーへ含めない。
- レイヤーのコピー・カット・貼付け・次ページ複製は準備を分割し、適用前の中断でデータと履歴を保つ。適用は1チェックポイント。プリセットIDも引き継ぐ。カード作成時に他ページのプリセット一覧を作り直さず、本文入力時はプリセット一覧を再構築しない。先行読込では既存カード・サムネイル・ジャンプ選択肢を移動・再作成せず、追加・順序変更の差分だけを反映する。
- Base64を使わない `.serifu` を初期保存形式に追加。原画像のバイト列、レイヤー、順序、状態、設定を保持する。コンテナ版1と編集モデル版6を分け、manifest上限16MiB、サイズ・参照・版・全長・実画像寸法を検証する。
- 従来JSON version 1〜6の読込とversion 6の出力を維持。JSONは専用Workerで解析・ページ単位で変換し、writerの完了を待って次へ進む。
- 一時保存は既存画像IDを一括取得し、新規画像だけを準備する。単一DBトランザクションでメタ情報・追加画像・削除画像を確定する。最後の画像要求の成功後もコミットまでは保存済みにしない。保存開始revision以後の編集は未保存として残す。
- Worker起動時に2D CanvasとPNG Blob生成を確認し、失敗は代替経路へ切り替える。同じ障害で毎画像の起動を繰り返さない。中断した稼働画像Workerは最大2秒で終了する。タイムアウト・クラッシュでも待機Promiseを確定する。JSON Workerの起動障害もメイン側へ切り替える。
- 従来JSONで同一の画像ソースが複数ページに使われる場合は原画像Blobと準備結果を操作内で共有する。取込元の画像IDやファイルハンドルは受け入れず、新規画像IDを発行する。高速形式と一時保存では、レイヤーを持つ未編集ページの状態も維持する。

- 単体：操作の終了状態・件数、順序を入れ替えたジョブ結果、容量制限、巨大な単一ジョブ、失敗、中断、レイヤー準備の非破壊性、LRUとキー、原画像バイト列の往復、コンテナ破損、ヘッダ寸法。
- 既存ブラウザ：入力・ドラッグ・レイヤーコピー・Undo/Redo・プリセット・元画像削除後の独立性・PNG・旧JSON・一時保存・自動保存・TXT・モバイル・500件の50/100/全表示。
- 追加bulk：同梱19書体と端末2書体のWorker/main RGBA完全一致。漢字フォールバック、句読点、台詞・吹き出し・キャプション輪郭・固定seedの先細りと掠れを含む。
- EXIF orientation=6のJPEGの寸法・向き・RGBA、および1フレームGIFを確認。透過はRGBA比較fixtureに含む。
- 読込中編集、中断した採用済みページの維持、直後の再操作、高速形式の初期選択・往復・一括PNGへの添付、PNG再生成0件の再保存、書込み失敗・中断、破損読込時の一覧維持、Worker非対応・起動クラッシュを確認。
- IndexedDBの要求途中でabortし、前回のメタ情報を保持することを確認。手動一時保存中の後続編集が保存後の変更として残り、新規画像1件だけを準備することを確認。
- カット準備中の取消でレイヤーとUndo履歴が変わらないことを確認。
- 静的ビルドを `/serifu-editor/` で配信し、Worker・書体の相対URLを確認。

既存検証には現行UIに存在しない文字交換ボタンと、プリセット追加前の「吹き出し・キャプションは記憶不可」という期待値が残っていた。文字交換は既存のモデル単体検証を維持し、ブラウザ側は現行の複製・Undoへ変更した。従来JSONの検証は形式を明示選択し、writerモックは逐次書込みをclose時に結合するよう更新した。

### PNG処理と段階計測

変更前の画像処理段階は、逐次デコード・draw・PNG生成の時間を各試行内で合算して中央値を取った。変更後は同じ処理を並列化し、PNG生成と書込みを含む経過時間で比較する。変更後には書込み待ちも含まれるため、純粋な画像処理の経過時間より長い。

| 画像 | 変更前の画像処理（秒） | 変更後のPNG生成＋書込み（秒） | 段階の経過時間短縮率 |
|---|---:|---:|---:|
| 小 | 7.40 | 1.92 | 74.0% |
| 中 | 34.88 | 13.83 | 60.3% |
| 重い | 55.33 | 24.96 | 54.9% |

## 追加修正：進捗表示とBrave環境の一括保存

ユーザー報告で、Brave環境の保存先選択APIが使えず、処理終了後も「準備」の進捗欄が残る経路を確認した。アプリ全体に合わせた暗色パネル・ライム色のバーへ変更し、完了・中断・失敗で非表示にする。結果は画面下部へ表示する。

保存先選択APIがない環境では、全画像／編集済み画像の対象PNGと選択形式の編集データを、非圧縮ZIPへまとめてダウンロードする。PNGの元寸法、描画、ページ番号、編集済み抽出、容量制限付き生成キュー、キャッシュを共用する。ダウンロード開始を報告し、ディスク保存完了や未保存状態の解除とは扱わない。

APIがある環境では保存先の選択と準備を独立段階として示し、選択待ち・フォルダ作成待ちを中断できる。遅れて戻った応答で保存を再開しない。API呼び出しの同期例外も共通の失敗処理へ渡す。

追加検証はZIPのUTF-8名・既知CRC32・元バイト列・中央ディレクトリ参照・取消・容量超過、読込と保存の終了時非表示、暗色の実画面、保存先待ちの取消と遅延応答、API非対応での編集済み／全件PNGと両編集データ形式、ZIP取消後の再操作。ZIPはPython標準ライブラリでも展開・CRCと収録件数を検証する。Brave実機の追加検証は未実施で、報告されたAPI非対応をChromium上で再現する。

上記の500枚性能値はこの追加修正前の記録。ZIPの500枚性能は未測定。ZIP作成は全体4GiB未満・最大65535ファイルに制限し、PNGの再圧縮は行わない。作成中は全収録Blobを保持するため、直接フォルダ保存より保持容量が増える。ダウンロード開始前の中断ではZIPを出力しない。

## 制約

実画像・実ディスク・Firefox/Safari/Edge実機は未確認。方向の全EXIF値、アニメーションGIFの全フレーム、AVIF実画像の互換、実OSの端末書体の差は網羅していない。非対応APIはメイン側へ戻り、1枚の重い同期描画中の即時中断は保証しない。

PNG予約には元画像画素数×4と余裕分を使い、巨大な単一結果は単独で扱う。これはブラウザ内部の物理メモリ上限を保証しない。サムネイル・原画像Blob・表示中Canvasも別途メモリを使う。

高速形式は従来版アプリで読めない。従来版へ渡す場合は「従来形式 (.json)」を選ぶ。途中失敗・中断した直接保存では、完了済みファイルや空ファイルが残る可能性がある。元ファイルは上書きしない。
