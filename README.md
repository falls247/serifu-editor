# Serifu Editor

複数画像にセリフ・漫画風効果音を配置するWebアプリ。左に元画像、中央にセリフ編集、右に位置調整付きプレビューを表示。画像ごとの3列が縦に並び、スクロールしながら連続編集できる。画像は外部送信せず、ブラウザ内で処理する。

公開版: https://falls247.github.io/serifu-editor/

## 編集

1. 「フォルダを開く」または「画像を追加」で複数画像を読み込む。画像名の数字順で並ぶ。
2. 各画像の中央で「＋ 男性」「＋ 女性」「✦ 効果音」を追加し、セリフを直接入力。入力欄は1行から始まり、改行数に合わせて自動で伸縮する。長い1行は横スクロールし、入力欄の自動折返しは行わない。
3. 男性セリフは黒、女性セリフはピンク。吹き出しなし、白い縁取りを必ず付ける。途中でも話者を切替できる。
4. 効果音の漫画エフェクトを選ぶ。「立体」は黒い立体影と傾き、「集中線」は放射線、「スピード」は流線、「震え」は文字ごとの角度・上下変化と震え線。効果音の文字色も変更できる。
5. 右のプレビューで文字をドラッグして移動。選択枠の右下の角でサイズ、上の丸で回転を調整。下の設定では元画像のピクセル単位でX/Y、文字サイズ、文字自体の太さ、回転、配置幅・高さ、白縁の太さ、縦書きを修正できる。
6. 「セリフ交換」は同じ画像内の2レイヤーのテキストだけを交換。男女の色・位置は保持。複製、削除、前後関係、画像別Undo/Redoにも対応。
7. 下へスクロールして次の画像を編集。「編集完了・次へ」は確認済みにして次へ移動。「文字を次の画像へ複製」は画像サイズに合わせて配置を拡縮し、次の画像の既存文字に追加する。
8. 「一括保存」で保存先の親フォルダを選ぶ。その中に日時とランダムID付きの新規フォルダを作り、全画像を元解像度のPNGと再編集用 `serifu-project.json` に保存。選択枠は出力しない。連番で同名の衝突を防ぐ。

## 縦書き・エフェクト・プリセット

セリフ・効果音の新規追加は縦書きが既定。効果音には極太のDela Gothic Oneと、細いハネ・払いを持つYuji Bokuの筆文字書体を用意する。プリセット「縦書き・感情／緊張の掠れ」「縦書き・強い縦ブラー」から始め、「ブラー・掠れ・ハネ・歪みの調整」で強さを変えられる。

セリフや効果音を選び、右側の「書体」で19種類から変更できる。新しい書体は初めて選んだ時にサイトから読み込み、読込完了後にプレビューを更新する。PNG保存は使用する書体の読込完了を待つ。書体と文字の太さの選択もプリセット・編集データ・一時保存に記憶する。

| 種類 | 書体 |
|---|---|
| 漫画・極太 | Dela Gothic One |
| 丸太・ポップ | Mochiy Pop One |
| 鋭角・力強い | Reggae One |
| 手描き角字 | RocknRoll One |
| 弾む極太かな | Darumadrop One（かな中心） |
| 太い手描きポップ | Potta One |
| やわらかい手書き | Klee One SemiBold |
| 細い丸文字 | Hachi Maru Pop |
| ラフな手書き | Yomogi |
| すっきり手書き | Zen Kurenaido |
| 筆文字・ハネ | Yuji Boku |
| 流れる筆文字 | Yuji Mai |
| 飾り明朝・太字 | Kaisei Decol Bold |
| 端正な筆文字 | Yuji Syuku |
| 白抜き・輪郭文字 | Train One |
| ドット・レトロ | DotGothic16 |
| 細い角字・棒文字 | Stick |
| ゴシック・明朝 | 端末に用意された書体（2種類） |

「文字の太さ（px）」は−10〜30、0.5刻みで指定。0は書体の標準、正の値は太く、負の値は細くする。文字サイズ・配置幅・白縁の太さは変えず、文字のインク部分を拡張／縮小するため、固定ウェイトの書体にも適用できる。大きく細くすると細い線が消える場合がある。書体にない文字は端末の代替書体で表示する。

プレビューで文字を選択して **Ctrl＋C／⌘＋C**、貼付け先のプレビューをクリックして **Ctrl＋V／⌘＋V**。文字内容、男女の区分、書体、太さ、エフェクト、配置をコピーする。別解像度の画像にはサイズと座標を合わせ、貼付けごとに20pxずつずらす。貼付け後は選択状態になり、ドラッグやUndo/Redoで修正できる。コピー後に元の文字を編集してもコピー内容は保持する。アプリ内の同じタブで使うコピー機能で、入力欄では通常の文字のコピー・貼付けが働く。

- 縦ブラー0〜300px・横ブラー0〜150pxを独立指定。文字を傾けてもブラーは配置枠の縦・横方向を保つ。全体の回転に合わせて方向も回転する。
- 滲みの強さ0〜400%と、元の文字の芯0〜100%を別指定。強い滲みと判読性を両立できる。
- 輪郭の荒れ、筆の掠れ、ハネ・払いはそれぞれ0〜100%。文字の実際の輪郭を削り、筆の繊維のような細い先端を伸ばす。掠れは入力文字から固定生成し、再描画・PNG保存・復元で変わらない。
- 流れる残像は最大300px。残像の方向、全方向ブラー、波打ち／膨張／先細り、傾き、縦横倍率も調整できる。
- 強い設定は文字の判読性を下げる。極端に大きい文字・倍率・ブラーでは内部描画の解像度を制限し、メモリの過剰確保を防ぐ。PNG自体は元画像の解像度で出力する。

「選択中の設定を記憶」で名前を付け、書式と配置をプリセットに保存する。文字内容・話者は含めない。選んだプリセットはセリフ／効果音それぞれの既定になり、＋ボタンと次の画像でも使用する。配置・文字サイズ・ブラー等は画像解像度に合わせて拡縮する。プリセットは同じブラウザに記憶し、編集データにも同梱する。

## 一時保存・自動保存

- 「一時保存」は元画像、編集情報と設定を同じブラウザのIndexedDBへ保存する。ファイル選択やダウンロードは不要。
- 自動保存は既定でON、2分周期。0.1〜1440分（6秒〜24時間）へ変更できる。変更がない場合は書き込まない。
- 再読込後は「保存した編集を復元」で前回の一覧に戻れる。編集中の一覧がある場合は置換前に確認する。
- 保存は画像と編集情報を一つのトランザクションで更新する。保存が失敗しても前回の保存を保持する。空き容量不足等は画面に表示する。
- 保存中の追加入力は次の周期で保存する。保存後の変更がある場合は状態表示に明示する。
- 一時保存は最新1件。同じブラウザの別タブで保存すると最新内容に置き換わる。別ブラウザ・別端末には引き継がれず、サイトデータ削除で消える。保管・持ち出しには「編集データを保存」を使用する。
- 復元後は元フォルダへ直接接続していないため、元画像削除は無効。

## 編集データ・元画像

「編集データを保存」は画像、男女の区分、効果音スタイル、文字と位置を1ファイルに含める。「編集データを読込」で現在の一覧に追加し、再編集できる。旧version 1の吹き出しは、テキストと位置を保って白縁の男性セリフに変換する。旧吹き出しの形状・しっぽは引き継がない。

- 編集は元画像を上書きしない。
- 「一覧から外す」は元ファイルを残す。未保存の当該画像の編集は失われる。
- 「元画像を削除」は、ファイル名を確認後、**実ファイルを完全削除**。ゴミ箱には移動しない。Undoでは復元できない。
- 元画像削除は「フォルダを開く」で直接接続した画像のみ。画像追加、サンプル、編集データからの画像には無効。
- 保存途中の失敗は保存済み枚数と出力フォルダを表示。部分出力は残る。
- ブラウザを閉じる前に一時保存または書き出しを確認する。自動保存周期の途中の変更は未保存。

## 起動・公開

Node.js 22以降を用意して実行。アプリ本体に依存パッケージは不要。

```bash
npm start
```

http://localhost:5173 を開く。Windowsから直接起動、またはWSLから起動してWindowsブラウザのlocalhostから利用できる。画像の選択はブラウザ側のファイルシステムで行う。

ローカルで公開版と同じ書体を用意する場合、初回に `npm run fonts` を実行する。公開時はCIで準備する。未準備時は端末の日本語書体を使用する。17種類の書体とそれぞれのOFLライセンスは[Google Fonts](https://github.com/google/fonts/tree/7085eb89a950e85db5b166b7a58d414544b4140c/ofl)の固定バージョンから取得し、チェックサムで検証する。書体は公開サイト自身から配信する。

GitHub Pagesは **Settings → Pages → Source → GitHub Actions** を設定。mainへのpushでチェック・テスト・ビルドを通過した版を自動公開する。Actionsの **Deploy GitHub Pages → Run workflow** からも実行できる。

```bash
npm run build
```

`_site/` へ公開用HTML/CSS/JavaScript、書体とライセンスを出力する。公開先にNode.jsサーバーは不要。

## 対応・制約

- 新規フォルダへの直接一括保存・元画像削除には File System Access API が必要。PC版Chrome / Edgeと、localhostまたはHTTPSが対象。
- 非対応ブラウザでも複数ファイル・フォルダからの読込、編集、編集データ保存を利用できる。新規フォルダへの直接一括保存・元ファイル削除は無効。
- デスクトップ・iPad横向きでは3列。狭い画面では元画像／セリフ／プレビューを順番に並べる。
- PNG出力。GIFは静止画として扱う。EXIF等のメタデータは引き継がない。基本のゴシック・明朝と代替書体は端末環境に依存。
- 縦書きは文字単位配置。高度な縦組み約物・ルビには未対応。長文が配置高さを超える場合は文字サイズか配置幅・高さを調整する。
- プレビューは最大1400pxの縮小表示で、出力は元解像度。大量・高解像度画像はメモリ使用量が大きくなるため分割編集を推奨。
- プレビューでCtrl/Cmd+C・V: 選択した文字のコピー・貼付け。矢印キー: 1px移動、Shift+矢印: 10px、Ctrl/Cmd+Z: 戻す、Shift追加: やり直す。

## 検証

```bash
npm run check
npm test
npm run build
```

GitHub Actionsでも実行。旧編集データ互換、画像別履歴、セリフ交換、別解像度への複製、回転後のヒット判定とファイル名を検証する。

Pages公開前にはPlaywrightによるブラウザ検証も実行。3列配置、連続編集、黒・ピンク・白縁の描画、ドラッグ、全効果音、編集データ再読込、旧データ変換を確認する。フォルダ保存と元画像削除はテスト用フォルダハンドルで検証し、ユーザーの実ファイルは使わない。ブラウザ検証用の依存はCI内だけに一時導入する。
